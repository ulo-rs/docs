The `ulo-http-rocket` crate wraps [Rocket](https://crates.io/crates/rocket) 0.5 to handle HTTP for Ulo applications, with same-port WebSocket upgrades via [`rocket_ws`](https://crates.io/crates/rocket_ws) 0.1. Request bodies are buffered (32 MiB cap); response bodies stream.

## Installation

```toml title="Cargo.toml"
[dependencies]
ulo = "0.2"
ulo-http-rocket = "0.1"
tokio = { version = "1", features = ["full"] }
```

## Basic setup

```rust
use ulo::*;
use ulo_http_rocket::RocketAdapter;

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let mut app = UloFactory::new().create_with(AppModule).await?;
    app.use_http_adapter(RocketAdapter::new(), ("127.0.0.1", 3000)).unwrap();
    app.start().await?;
    Ok(())
}
```

Routes are not translated into Rocket's `<param>` syntax. The adapter mounts one catch-all Rocket route per method at `/<__ulo_chain..>` and dispatches through an internal matcher that understands Ulo's `{param}` syntax itself, along with `:param` and `*tail` for callers of the raw adapter SPI. Unmatched paths get Ulo's standard 404 envelope, and the global middleware chain observes every request.

## WebSocket support

Same-port gateways (`#[websocket_gateway("/path")]`) upgrade through `rocket_ws` on the HTTP listener; the routes are mounted as `GET`, matching RFC 6455.

No sub-protocol is negotiated: the handshake reply carries `Sec-WebSocket-Accept` and nothing else. `ulo-http-axum`, `ulo-http-salvo`, and `ulo-http-poem` each echo back the first protocol the client offered. A client that requires the server to select one — a `graphql-transport-ws` client does — refuses the connection on this adapter.

The adapter does **not** implement `WebSocketAdapter`, so separate-port gateways (`#[websocket_gateway("/path", port = N)]`) fail registration. Pair `ulo-http-rocket` with a dedicated separate-port adapter ([`ulo-ws-tungstenite`](/docs/websocket/separate-port)) when you need one.

## Body behavior

- **Requests are buffered**, capped at 32 MiB. Rocket's `Data<'r>` is lifetime-bound to the request and cannot outlive the handler, so the adapter reads the full body into memory before handing it to Ulo. The `BodyStream` extractor still works — it sees the payload as a single chunk.
- **Responses stream.** `Body::stream(...)` is bridged into Rocket's `streamed_body`, so chunks reach the client incrementally — [SSE](/docs/techniques/sse) works. Buffered bodies are sent with an accurate `Content-Length` instead of chunked transfer.

## Graceful shutdown

The adapter forwards Ulo's shutdown signal to Rocket's `Shutdown::notify()`; the launch future resolves once Rocket has drained in-flight connections. Rocket's own Ctrl-C handling is disabled (`shutdown.ctrlc = false`), so signal wiring goes through the application's [`shutdown_handle()`](/docs/deployment/production#graceful-shutdown) like every other adapter.

## Quirks

- **A pre-bound listener is refused.** Rocket binds inside `launch()` from its own figment configuration, with no seam for a socket that is already listening. Passing a `std::net::TcpListener` as the bind target fails at `app.bind()` with `StartupError::Adapter { transport: "http", .. }` naming the limitation. Socket activation and listener hand-off across restarts need one of the other four adapters — see [Bind Targets](/docs/techniques/bind-targets).
- **Hostname must be an IP literal.** The hostname is parsed as an `IpAddr` for Rocket's config; a DNS name like `"localhost"` falls back to `127.0.0.1`. Pass `"127.0.0.1"` or `"0.0.0.0"` explicitly.
- **Port 0 works via a liftoff fairing.** Rocket fuses bind and serve into `launch()` with no public pre-serve hook, so the adapter captures the OS-assigned address in an `on_liftoff` fairing. `app.bind()` still returns the real address in `BoundAdapters` — dynamic ports behave like every other adapter.
