The `ulo-http-axum` crate wraps [Axum](https://github.com/tokio-rs/axum) 0.8 to handle HTTP for Ulo applications. It implements both `HttpAdapter` and `WebSocketAdapter`, streams bodies in both directions, and is the recommended choice for most applications.

## Installation

```toml title="Cargo.toml"
[dependencies]
ulo = "0.2"
ulo-http-axum = "0.1"
tokio = { version = "1", features = ["full"] }
```

## Basic setup

```rust
use ulo::*;
use ulo_http_axum::AxumAdapter;

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let mut app = UloFactory::new().create_with(AppModule).await?;
    app.use_http_adapter(AxumAdapter::new(), ("127.0.0.1", 3000)).unwrap();
    app.start().await?;
    Ok(())
}
```

`use_http_adapter` registers all routes from the module tree onto the adapter. `start()` binds the socket and serves until shutdown; bind failures (port in use) surface as the returned error.

Ulo's `{param}` path syntax matches Axum's, so routes mount unchanged. An unmatched path hits a fallback that returns Ulo's standard 404 envelope. A method mismatch is answered by Axum's own router instead — an empty body with an `Allow` header, not the Ulo envelope that `ulo-http-actix`, `ulo-http-salvo`, and `ulo-http-rocket` build for a 405. The global middleware chain runs on both.

## Global enhancers

Global middleware, guards, and error handlers are registered on the factory before the app is created:

```rust
use std::sync::Arc;
use ulo::*;
use ulo_http_axum::AxumAdapter;

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let mut factory = UloFactory::new();
    factory
        .use_global_middleware(Arc::new(LoggerMiddleware))
        .use_global_http_guards(Arc::new(ThrottleGuard::default()))
        .use_global_http_error_handler(Arc::new(GlobalErrorHandler));

    let mut app = factory.create_with(AppModule).await?;
    app.use_http_adapter(AxumAdapter::new(), ("0.0.0.0", 3000)).unwrap();
    app.start().await?;
    Ok(())
}
```

Guards, interceptors, and error handlers are registered per transport (`use_global_http_*`, `use_global_rpc_*`, `use_global_ws_*`, `use_global_grpc_*`); `use_global_middleware` is HTTP-wide. For CORS, see [CORS](/docs/techniques/cors).

## Streaming bodies

Both directions stream:

- **Requests** are handed to Ulo as a stream — the `BodyStream` extractor sees frames as they arrive; `Bytes`, `Json`, and friends collect on demand.
- **Responses** built with `Body::stream(...)` reach the client chunk by chunk, so [SSE](/docs/techniques/sse) and long-lived streaming responses work without buffering.

## WebSocket support

Same-port gateways (`#[websocket_gateway("/path")]`) are wired onto the HTTP listener automatically — registering the HTTP adapter is enough:

```rust
let mut app = UloFactory::new().create_with(AppModule).await?;
app.use_http_adapter(AxumAdapter::new(), ("127.0.0.1", 3000)).unwrap();
app.start().await?;
```

Separate-port gateways (`#[websocket_gateway("/path", port = N)]`) need a `WebSocketAdapter` as well — register a second `AxumAdapter` instance:

```rust
app.use_http_adapter(AxumAdapter::new(), ("127.0.0.1", 3000)).unwrap();
app.use_websocket_adapter(AxumAdapter::new()).unwrap();
```

Sub-protocols are negotiated by echoing the first protocol the client offers in `Sec-WebSocket-Protocol`. See [WebSocket Gateways](/docs/websocket/gateways) for gateway definitions.

## Graceful shutdown

The adapter forwards Ulo's shutdown signal to Axum's `with_graceful_shutdown`, so in-flight requests drain before the serve loop exits. Trigger it via the application's [`shutdown_handle()`](/docs/deployment/production#graceful-shutdown) — the framework installs no signal handlers of its own.

If the serve loop fails after a successful bind, the adapter logs the error and the serve future returns — which the framework treats as a shutdown signal, closing the whole application through the same graceful drain. No process exit is involved.

## Tower layers

Any [`tower::Layer`](https://docs.rs/tower/latest/tower/trait.Layer.html) can run as Ulo middleware via `TowerLayer`. This requires the `tower-compat` feature on `ulo`:

```toml title="Cargo.toml"
[dependencies]
ulo = { version = "0.2", features = ["tower-compat"] }
```

Register globally, or scope to routes in a module's `configure_middleware` — `apply_tower(layer)` is sugar for `apply(TowerLayer::new(layer))`:

```rust
use std::sync::Arc;
use ulo::tower_compat::TowerLayer;
use tower_http::trace::TraceLayer;

// Global — every request
factory.use_global_middleware(Arc::new(TowerLayer::new(TraceLayer::new_for_http())));

// Scoped — specific routes only
fn configure_middleware(&self, consumer: &mut MiddlewareConsumer) {
    consumer
        .apply_tower(TraceLayer::new_for_http())
        .for_routes(vec!["/api/*"]);
}
```

<Callout type="warn">
`TowerLayer` is Ulo middleware, not an Axum feature — the same registration works on every HTTP adapter. One limitation: layers that call the inner service more than once (`tower::retry`, `tower::hedge`) panic at runtime; use an interceptor for retry logic.
</Callout>

## Runtime tuning

`ulo-http-axum` delegates threading to Tokio. For worker-thread counts and other runtime settings, build the runtime explicitly:

```rust
fn main() -> anyhow::Result<()> {
    tokio::runtime::Builder::new_multi_thread()
        .worker_threads(4)
        .enable_all()
        .build()
        .unwrap()
        .block_on(async {
            let mut app = UloFactory::new().create_with(AppModule).await?;
            app.use_http_adapter(AxumAdapter::new(), ("0.0.0.0", 3000)).unwrap();
            app.start().await
        })
}
```

## HTTPS/TLS

The adapter binds a plain TCP listener; there is no hook for terminating TLS in-process. Terminate TLS at a load balancer or reverse proxy (nginx, Cloudflare, etc.) — see [Production](/docs/deployment/production#reverse-proxy-nginx).
