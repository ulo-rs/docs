The `toni-actix` crate integrates Toni with [Actix-web](https://actix.rs/) 4. It implements `HttpAdapter` only — no WebSocket support — and buffers request and response bodies. Reach for it when you're integrating Toni into an existing Actix-web deployment.

## Installation

```toml title="Cargo.toml"
[dependencies]
toni = "0.2"
toni-actix = "0.1"
actix-web = "4"
```

## Basic setup

```rust
use toni::*;
use toni_actix::ActixAdapter;

#[actix_web::main]
async fn main() -> anyhow::Result<()> {
    let mut app = ToniFactory::new().create_with(AppModule).await?;
    app.use_http_adapter(ActixAdapter::new(), ("127.0.0.1", 3000)).unwrap();
    app.start().await?;
    Ok(())
}
```

The Toni API surface is identical to the other adapters — controllers, guards, interceptors, extractors, and global middleware all work the same. Toni and Actix share `{param}` path syntax, so routes mount unchanged.

## Graceful shutdown

The adapter forwards Toni's shutdown signal to Actix's server handle with graceful stop, so worker threads finish in-flight requests before exiting. Trigger it via the application's [`shutdown_handle()`](/docs/deployment/production#graceful-shutdown) — the framework installs no signal handlers of its own.

## Limitations

- **No WebSocket.** The adapter implements neither same-port upgrades nor the `WebSocketAdapter` trait. A `#[websocket_gateway]` cannot be served through `toni-actix` on the HTTP port; pair it with a separate-port WebSocket adapter ([`toni-tungstenite`](/docs/websocket/separate-port)) for gateways declared with `port = N`.
- **Buffered request bodies.** The full body is read into memory before the handler runs. The `BodyStream` extractor still works, but sees the payload as a single chunk.
- **Buffered response bodies.** The response body is collected in full before it is sent. Streaming responses — [SSE](/docs/techniques/sse), large downloads built with `Body::stream` — do not work on this adapter; an unbounded stream never completes. Use `toni-axum`, `toni-salvo`, or `toni-poem` for streaming workloads.

## When to choose Actix

- You're migrating from or embedding into an existing Actix-web application
- Your workload is plain request/response JSON with no streaming or WebSocket needs
