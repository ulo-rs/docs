The `ulo-http-actix` crate integrates Ulo with [Actix-web](https://actix.rs/) 4. It implements `HttpAdapter` only — no WebSocket support — and buffers request and response bodies. Reach for it when you're integrating Ulo into an existing Actix-web deployment.

## Installation

```toml title="Cargo.toml"
[dependencies]
ulo = "0.2"
ulo-http-actix = "0.1"
actix-web = "4"
```

## Basic setup

```rust
use ulo::*;
use ulo_http_actix::ActixAdapter;

#[actix_web::main]
async fn main() -> anyhow::Result<()> {
    let mut app = UloFactory::new().create_with(AppModule).await?;
    app.use_http_adapter(ActixAdapter::new(), ("127.0.0.1", 3000)).unwrap();
    app.start().await?;
    Ok(())
}
```

The Ulo API surface is identical to the other adapters — controllers, guards, interceptors, extractors, and global middleware all work the same. Ulo and Actix share `{param}` path syntax, so routes mount unchanged.

## Graceful shutdown

The adapter forwards Ulo's shutdown signal to Actix's server handle with graceful stop, so worker threads finish in-flight requests before exiting. Trigger it via the application's [`shutdown_handle()`](/docs/deployment/production#graceful-shutdown) — the framework installs no signal handlers of its own.

## Limitations

- **No WebSocket.** The adapter implements neither same-port upgrades nor the `WebSocketAdapter` trait. A `#[websocket_gateway]` cannot be served through `ulo-http-actix` on the HTTP port; pair it with a separate-port WebSocket adapter ([`ulo-ws-tungstenite`](/docs/websocket/separate-port)) for gateways declared with `port = N`.
- **Buffered request bodies, capped at 256 KiB.** The full body is read into memory before the handler runs, and a request over 262 144 bytes is answered `413 Payload Too Large` before any handler, guard or middleware sees it. The ceiling is actix-web's `PayloadConfig` default, which this adapter never raises, so there is no ulo knob for it — a handler that accepts uploads on axum starts refusing them here at a threshold 128× smaller than rocket's. The `BodyStream` extractor still works, but sees the payload as a single chunk.
- **Buffered response bodies.** The response body is collected in full before it is sent. Streaming responses — [SSE](/docs/techniques/sse), large downloads built with `Body::stream` — do not work on this adapter; an unbounded stream never completes. Use `ulo-http-axum`, `ulo-http-salvo`, or `ulo-http-poem` for streaming workloads.

## When to choose Actix

- You're migrating from or embedding into an existing Actix-web application
- Your workload is plain request/response JSON with no streaming or WebSocket needs
