title: Custom Adapters
description: Implement the HttpAdapter trait to integrate Toni with any HTTP server.
---

If none of the five official adapters fits your constraints, implement `HttpAdapter` to back Toni with any HTTP server. The contract has three parts: store routes during `register_route`, optionally accept WebSocket paths in `register_ws_route`, and consume yourself into a self-contained lifecycle handle in `into_lifecycle`.

## The contract

```rust
#[toni::async_trait]
pub trait HttpAdapter: Send + Sync + 'static {
    fn register_route(
        &mut self,
        method: HttpMethod,
        path: &str,
        handler: Arc<dyn RequestHandler>,
    ) -> Result<()>;

    // Optional — default returns an error. Implement for same-port WebSocket.
    fn register_ws_route(&mut self, path: &str, callbacks: Arc<WsConnectionCallbacks>) -> Result<()>;

    async fn into_lifecycle(
        self: Box<Self>,
        target: BindTarget,
        ctx: AdapterContext,
    ) -> Result<HttpLifecycleHandle>;
}
```

Everything you need is exported from the `toni` crate root: `HttpAdapter`, `HttpMethod`, `RequestHandler`, `AdapterContext`, `BindTarget`, `HttpLifecycleHandle`, `HttpRequest`, `HttpResponse`, `WsConnectionCallbacks`, plus `http_helpers::{PathParams, RequestBody}`.

**`register_route`** is called at bootstrap for every route the framework discovers. Store the `(method, path, handler)` triple; build the native router later. Each `Arc<dyn RequestHandler>` wraps one route's full pipeline — route-scoped middleware, guards, interceptors, and the controller — behind a single call:

```rust
pub trait RequestHandler: Send + Sync + 'static {
    fn handle(&self, req: HttpRequest) -> BoxFuture<HttpResponse>;
}
```

**`into_lifecycle`** consumes the adapter and does three things:

1. **Builds the native router** from the stored routes and anchors the global middleware chain around it (see below).
2. **Acquires the listener synchronously**, before returning — port conflicts then surface as `StartupError::Adapter { transport: "http", .. }` from `app.bind()` instead of failing inside a spawned task. `BindTarget::into_std_listener` handles both target forms: it binds an address, and passes through a listener the caller supplied. If the underlying server cannot serve on an existing listener, match on the target and return an error for `BindTarget::Listener` instead.
3. **Returns a handle** built from the bound address, the long-running serve future, and a closure that triggers graceful shutdown:

```rust
impl HttpLifecycleHandle {
    pub fn new<F, Fut>(
        local_addr: SocketAddr,
        serve: Pin<Box<dyn Future<Output = ()> + Send + 'static>>,
        shutdown: F,
    ) -> Self
    where
        F: FnOnce() -> Fut + Send + Sync + 'static,
        Fut: Future<Output = Result<()>> + Send + 'static;
}
```

The handle owns everything; the framework never calls back into the adapter after `into_lifecycle`.

## Running the global chain

`AdapterContext` carries the global middleware chain. Anchor `ctx.execute` at the adapter's outermost point, wrapping the entire native router — routing runs inside the closure, not before it:

```rust
let http_res = ctx
    .execute(http_req, move |req| {
        let router = router.clone();
        Box::pin(async move { router.dispatch(req).await })  // match + handle + 404 fallback
    })
    .await;
```

Anchored this way, the chain observes every request: matched routes, unknown paths (404), method mismatches (405), and same-port WebSocket upgrades. A middleware can short-circuit by returning a response without invoking the closure, which is how CORS preflight is answered. The closure receives the request the chain forwards: a middleware that rewrites the URI changes which route matches. Wrapping individual matched-route handlers instead breaks all of this — 405s and preflight would be answered by the native router before the chain ever runs.

The router's catch-all for unmatched paths produces Toni's standard 404 envelope (`{"statusCode": 404, "message": "Cannot GET /x", "error": "Not Found"}`) — the official adapters all do.

## Converting requests and responses

Toni's `HttpRequest` is built from `http::request::Parts` plus a body:

```rust
// Streaming — hand frames through as they arrive (preferred):
let req = HttpRequest::from_parts(parts, RequestBody::Streaming(boxed_body));

// Buffered — when the native server can't stream (e.g. toni-rocket):
let req = HttpRequest::from_parts(parts, RequestBody::Buffered(bytes));
```

Path parameters go into the parts' extensions before constructing the request — the `Path<T>` extractor reads them from there:

```rust
parts.extensions.insert(PathParams(params)); // HashMap<String, String>
```

Going the other way, `HttpResponse` is a plain struct — `status: u16`, `headers: Vec<(String, String)>`, `body: Option<Body>` — that you translate into your server's native response. `Body` exposes `content_type()` and `into_box_body()`; forward the body as a stream if your server supports it, so `Body::stream` responses (SSE) reach the client incrementally.

## Skeleton

Abridged from `toni-axum` — every shown signature is real:

```rust
use std::sync::Arc;
use anyhow::Result;
use tokio::sync::watch;
use toni::{
    AdapterContext, BindTarget, HttpAdapter, HttpLifecycleHandle, HttpMethod,
    HttpRequest, HttpResponse, RequestHandler,
    http_helpers::{PathParams, RequestBody},
};

pub struct MyAdapter {
    routes: Vec<(HttpMethod, String, Arc<dyn RequestHandler>)>,
    shutdown_tx: Arc<watch::Sender<bool>>,
}

impl MyAdapter {
    pub fn new() -> Self {
        let (tx, _) = watch::channel(false);
        Self { routes: Vec::new(), shutdown_tx: Arc::new(tx) }
    }
}

#[toni::async_trait]
impl HttpAdapter for MyAdapter {
    fn register_route(
        &mut self,
        method: HttpMethod,
        path: &str,
        handler: Arc<dyn RequestHandler>,
    ) -> Result<()> {
        self.routes.push((method, path.to_owned(), handler));
        Ok(())
    }

    async fn into_lifecycle(
        mut self: Box<Self>,
        target: BindTarget,
        ctx: AdapterContext,
    ) -> Result<HttpLifecycleHandle> {
        let routes = std::mem::take(&mut self.routes);
        let ctx = Arc::new(ctx);

        // 1. Build the native router. Each matched route's native handler:
        //    - converts the native request into parts + body,
        //    - inserts PathParams into parts.extensions,
        //    - builds HttpRequest::from_parts(parts, RequestBody::Streaming(body)),
        //    - calls handler.handle(req) directly (no ctx.execute here),
        //    - converts the HttpResponse back to the native type.
        //    Include a catch-all that renders the 404 envelope. Then wrap the
        //    whole router in an outer service that converts the inbound request
        //    and runs ctx.execute(http_req, |req| route(req)) — the global chain
        //    anchors around routing, not inside handlers.
        // …

        // 2. Acquire the socket synchronously — port conflicts surface at
        //    app.bind(). into_std_listener binds an address target and passes
        //    a caller-supplied listener through.
        let std_listener = target.into_std_listener()?;
        std_listener.set_nonblocking(true)?;
        let listener = tokio::net::TcpListener::from_std(std_listener)?;
        let local_addr = listener.local_addr()?;

        // 3. Serve future + shutdown closure.
        let mut shutdown_rx = self.shutdown_tx.subscribe();
        let serve = Box::pin(async move {
            // drive the server, stopping when shutdown_rx flips to true
            // …
        });

        let shutdown_tx = self.shutdown_tx.clone();
        Ok(HttpLifecycleHandle::new(local_addr, serve, move || async move {
            let _ = shutdown_tx.send(true);
            Ok(())
        }))
    }
}
```

Register it like any official adapter:

```rust
let mut app = ToniFactory::new().create_with(AppModule).await?;
app.use_http_adapter(MyAdapter::new(), ("127.0.0.1", 3000)).unwrap();
app.start().await?;
```

## WebSocket support

For same-port upgrades, implement `register_ws_route` and perform the upgrade in your router. The framework hands you `WsConnectionCallbacks` per gateway path; the adapter drives the connection lifecycle:

- `callbacks.connect(parts, sender).await` when a client connects — pass the upgrade request parts and an adapter-owned `Arc<dyn WsSink>`; returns the assigned client id, or an error when a guard rejects the connection.
- `callbacks.message(client_id, msg).await` for each decoded frame — returns a `MessageCallbackResult` (`Continue`, `Stop`, or `Stream(stream)` to spawn a forwarding task).
- `callbacks.disconnect(client_id).await` when the read loop ends.

For separate-port gateways (`#[websocket_gateway(port = N)]`), implement the `WebSocketAdapter` trait on the same type — `register_gateway(port, path, callbacks)` plus `into_lifecycle_handles(targets: Vec<(u16, BindTarget)>)` returning one `WsLifecycleHandle` per entry. The `u16` in each pair is the declared `port = N` — the key the callbacks were stored under in `register_gateway`, not where to listen. Where to listen is the `BindTarget`, whose socket may sit on a different port; report the socket's actual address through the handle.

## Reference implementations

The five in-repo crates are the canonical references, in roughly ascending complexity:

- [`toni-poem`](https://github.com/ifeanyi-ugwu/toni-rs/tree/master/toni-poem) — near-zero body conversion, both WebSocket modes
- [`toni-axum`](https://github.com/ifeanyi-ugwu/toni-rs/tree/master/toni-axum) — path-syntax rewrite, both WebSocket modes
- [`toni-salvo`](https://github.com/ifeanyi-ugwu/toni-rs/tree/master/toni-salvo) — trait-object handlers, method-mapping workarounds
- [`toni-actix`](https://github.com/ifeanyi-ugwu/toni-rs/tree/master/toni-actix) — the buffered, HTTP-only minimum
- [`toni-rocket`](https://github.com/ifeanyi-ugwu/toni-rs/tree/master/toni-rocket) — buffered requests, fairing-based address discovery
