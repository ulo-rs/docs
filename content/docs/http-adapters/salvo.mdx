The `ulo-http-salvo` crate wraps [Salvo](https://salvo.rs) 0.92 to handle HTTP for Ulo applications. It implements both `HttpAdapter` and `WebSocketAdapter`, so a single adapter type covers HTTP routes, same-port WebSocket upgrades, and separate-port WebSocket servers. Bodies stream in both directions.

## Installation

```toml title="Cargo.toml"
[dependencies]
ulo = "0.2"
ulo-http-salvo = "0.1"
tokio = { version = "1", features = ["full"] }
```

## Basic setup

```rust
use ulo::*;
use ulo_http_salvo::SalvoAdapter;

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let mut app = UloFactory::new().create_with(AppModule).await?;
    app.use_http_adapter(SalvoAdapter::new(), ("127.0.0.1", 3000)).unwrap();
    app.start().await?;
    Ok(())
}
```

Ulo and Salvo share `{param}` path syntax, so routes mount unchanged. A catch-all at `{**rest}` returns Ulo's standard 404 envelope for unmatched paths, with the global middleware chain applied.

## WebSocket support

Same-port gateways (`#[websocket_gateway("/path")]`) upgrade on the HTTP listener automatically. Separate-port gateways (`port = N`) need a second instance registered as the WebSocket adapter:

```rust
app.use_http_adapter(SalvoAdapter::new(), ("127.0.0.1", 3000)).unwrap();
app.use_websocket_adapter(SalvoAdapter::new()).unwrap();
```

`port = 0` lets the OS assign a distinct listener. Sub-protocols are negotiated by echoing the first protocol the client offers in `Sec-WebSocket-Protocol`.

## Streaming bodies

- **Requests** are forwarded as a stream rather than buffered. `BodyStream` receives frames as they arrive; `Bytes`, `Json`, and friends collect on demand. Salvo's default 64 KiB body cache is bypassed — **there is no built-in size limit** on what reaches the handler. Add a limit via middleware or a reverse proxy if you need one.
- **Responses** built with `Body::stream(...)` are forwarded as chunks, so [SSE](/docs/techniques/sse) and long-lived streaming responses work without buffering.

## Graceful shutdown

The adapter forwards Ulo's shutdown signal to `salvo::Server::handle().stop_graceful(None)`. The HTTP server and every separate-port WebSocket listener stop in response to a single signal. Trigger it via the application's [`shutdown_handle()`](/docs/deployment/production#graceful-shutdown) — the framework installs no signal handlers of its own.

## TRACE and CONNECT quirk

GET, POST, PUT, DELETE, PATCH, HEAD, and OPTIONS dispatch through Salvo's exact-method router filters. Salvo's `Router` exposes no `.trace()` or `.connect()`, so TRACE and CONNECT routes are attached via `Router::goal()` — **the handler runs on a path match regardless of method**. Don't give a TRACE or CONNECT route the same path as handlers that expect exact-method dispatch.
