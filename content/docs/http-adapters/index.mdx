---
title: HTTP Adapters Overview
description: Why Ulo separates application logic from the HTTP runtime, and how to choose between the five official adapters.
---

Ulo doesn't handle HTTP itself. That concern belongs to the **adapter** — a thin integration layer that bridges Ulo's routing and DI system to an actual HTTP server.

This separation means your application logic is completely decoupled from the HTTP runtime. Switching adapters is a one-line change in `main.rs`.

## Official adapters

Five adapter crates ship with the framework:

| | `ulo-http-axum` | `ulo-http-actix` | `ulo-http-salvo` | `ulo-http-poem` | `ulo-http-rocket` |
|---|---|---|---|---|---|
| **Underlying framework** | Axum 0.8 | Actix-web 4 | Salvo 0.92 | Poem 3.1 | Rocket 0.5 |
| **Request bodies** | Streamed | Buffered (256 KiB cap) | Streamed | Streamed | Buffered (32 MiB cap) |
| **Response bodies** | Streamed | Buffered | Streamed | Streamed | Streamed |
| **Same-port WebSocket** | Yes | No | Yes | Yes | Yes (`rocket_ws`) |
| **Separate-port WebSocket** | Yes | No — pair `ulo-ws-tungstenite` | Yes | Yes | No — pair `ulo-ws-tungstenite` |
| **SSE / streaming responses** | Yes | No | Yes | Yes | Yes |
| **Graceful shutdown** | Yes | Yes | Yes | Yes | Yes |
| **Pre-bound listener** | Yes | Yes | Yes | Yes | No |
| **405 response body** | Native | Ulo envelope | Ulo envelope | Native | Ulo envelope |

`ulo-http-axum`, `ulo-http-salvo`, and `ulo-http-poem` cover the full capability surface: streaming in both directions and WebSocket in both deployment modes. `ulo-http-axum` is the default choice — it pairs naturally with the Tokio ecosystem (sqlx, reqwest, tonic).

Reach for `ulo-http-actix` or `ulo-http-rocket` when you're integrating into an existing Actix-web or Rocket deployment. Both buffer request bodies; `ulo-http-actix` also buffers responses, which rules out SSE and streaming downloads on that adapter.

A 404 is Ulo's `{statusCode, message, error}` envelope on every adapter. A 405 is not: `ulo-http-actix`, `ulo-http-salvo`, and `ulo-http-rocket` build the same envelope and add an `Allow` header, while `ulo-http-axum` and `ulo-http-poem` let their own router answer — an empty body on Axum, the text `method not allowed` on Poem, and only Axum sets `Allow`. A client that parses the error body needs to tolerate both shapes, or the application needs a global middleware that rewrites the 405 it sees on the way out.

[`ulo-ws-tungstenite`](/docs/websocket/separate-port) is what fills the two gaps in the separate-port row — it implements `WebSocketAdapter` and nothing else, so it registers alongside any HTTP adapter.

## The HttpAdapter trait

Any HTTP server can back a Ulo application by implementing `HttpAdapter`:

```rust
#[ulo::async_trait]
pub trait HttpAdapter: Send + Sync + 'static {
    /// Register one HTTP route. Called at bootstrap for every route
    /// the framework discovers.
    fn register_route(
        &mut self,
        method: HttpMethod,
        path: &str,
        handler: Arc<dyn RequestHandler>,
    ) -> Result<()>;

    /// Register a WebSocket upgrade path on the same port as HTTP.
    /// The default implementation returns an error — only adapters
    /// with same-port WebSocket support implement it.
    fn register_ws_route(&mut self, path: &str, callbacks: Arc<WsConnectionCallbacks>) -> Result<()>;

    /// Consume the adapter, acquire the listening socket, and return a
    /// self-contained lifecycle handle the framework drives.
    async fn into_lifecycle(
        self: Box<Self>,
        target: BindTarget,
        ctx: AdapterContext,
    ) -> Result<HttpLifecycleHandle>;
}
```

The lifecycle:

1. `app.use_http_adapter(adapter, ("127.0.0.1", 3000))` boxes the adapter (`UloApplication` holds it as `Box<dyn HttpAdapter>`) and calls `register_route` for every resolved route.
2. `app.bind()` calls `into_lifecycle`, which acquires the socket synchronously — port conflicts surface here as `StartupError::Adapter { transport: "http", .. }`, not inside a background task. Registration completes for every transport the application declares before any socket is acquired, so a declaration that cannot work fails with nothing bound. `ulo-rpc-tcp` and `ulo-rpc-udp` sit outside that ordering — each takes its socket while registering, so a port conflict on either is reported before another transport's misconfiguration is. The returned [`BoundAdapters`](/docs/api-reference/core) carries the bound addresses, so passing port `0` and reading the OS-assigned port works.
3. `app.run()` drives the serve loop until [`shutdown_handle()`](/docs/deployment/production#graceful-shutdown) is triggered; a serve loop that returns on its own also shuts down the whole application. `app.start()` is `bind()` + `run()` in one step.

The `AdapterContext` passed to `into_lifecycle` carries the global middleware chain; every adapter runs it *before* its own routing, so global middleware observes every request — including 404s, 405s, and same-port WebSocket upgrades — and a request rewritten in the chain changes which route matches.

## Where to listen

`BindTarget` is either an address to bind or a socket that is already listening. A `(host, port)` tuple converts to the first form, a `std::net::TcpListener` to the second:

```rust
// Bind an address — the common case.
app.use_http_adapter(AxumAdapter::new(), ("127.0.0.1", 3000))?;

// Serve on a socket you bound yourself.
let listener = std::net::TcpListener::bind("127.0.0.1:3000")?;
app.use_http_adapter(AxumAdapter::new(), listener)?;
```

The second form matters when something outside the process owns the socket. A supervisor that holds the listener across restarts keeps the port answering while the application is replaced: connections queue in the kernel backlog instead of being refused. That turns a rebuild in development into added latency rather than a wall of connection errors, and it is what makes systemd socket activation and zero-downtime restarts work. Tests use it to bind port `0` themselves and keep the address, with no window for another process to take the port.

Pair it with [`listenfd`](https://crates.io/crates/listenfd) to pick up a socket passed in by systemd or [`systemfd`](https://crates.io/crates/systemfd):

```rust
let mut fds = listenfd::ListenFd::from_env();
let target: ulo::BindTarget = match fds.take_tcp_listener(0)? {
    Some(listener) => listener.into(),
    None => ("127.0.0.1", 3000).into(),
};
app.use_http_adapter(AxumAdapter::new(), target)?;
```

Ulo reads no environment protocol itself — it accepts a listener and asks nothing about where it came from, so any supervisor works.

`ulo-http-rocket` is the exception: Rocket binds inside `launch()` from its own configuration, so passing it a listener fails at `app.bind()` with an error naming the limitation.

See [Development Workflow](/docs/getting-started/development-workflow) for the watch-restart loop, and [Bind Targets](/docs/techniques/bind-targets) for the full surface — including listener adoption on the WebSocket, TCP, UDP, and gRPC transports.

## Bounded in-flight requests

Unlike the RPC and gRPC adapters, HTTP adapters expose no `with_max_inflight` knob. Concurrency limiting has three cleaner homes:

1. **Global middleware** — a semaphore-backed `Middleware` registered via `factory.use_global_middleware(...)` works uniformly on every HTTP adapter.
2. **Framework-native layers** — `tower::limit::GlobalConcurrencyLimitLayer` on axum/poem (via [`tower-compat`](/docs/http-adapters/axum#tower-layers)), Actix-web middleware, or a Rocket fairing.
3. **A reverse proxy** (nginx, HAProxy) handling rate-limiting at the network layer.
