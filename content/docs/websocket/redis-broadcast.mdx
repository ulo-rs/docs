---
title: Redis Broadcast
description: Scale WebSocket broadcasts across multiple processes with ulo-ws-redis.
---

`ulo-ws-redis` replaces the in-process `BroadcastModule` with a Redis-backed broadcaster. Every `send()` call publishes to a Redis Pub/Sub channel; a background subscriber loop on each process delivers messages to locally connected clients.

Use this when running multiple instances of the same service and needing clients on different processes to receive the same WebSocket messages.

## Installation

```toml title="Cargo.toml"
[dependencies]
ulo = "0.2"
ulo-ws-redis = "0.1"
```

## Setup

Replace `BroadcastModule::new()` with `RedisBroadcastModule::for_root(url)` in your module:

```rust
use ulo_ws_redis::RedisBroadcastModule;

#[module(
    imports: [RedisBroadcastModule::for_root("redis://127.0.0.1:6379")],
    providers: [ChatGateway, ChatService],
)]
pub struct AppModule;
```

`for_root` returns a **global** `DynamicModule`. It registers both `BroadcastService` (used internally by the gateway wiring) and `RedisBroadcastService` (your injectable for sending messages).

## Injecting RedisBroadcastService

Inject `RedisBroadcastService` anywhere you need to push messages across processes:

```rust
use ulo_ws_redis::RedisBroadcastService;
use ulo::websocket::{WsClient, WsError, WsHandlerOutput, WsMessage};
use ulo::WsHandlerResult;
use ulo::{new, subscriptions, websocket_gateway};

#[websocket_gateway("/chat")]
pub struct ChatGateway {
    #[inject]
    broadcast: RedisBroadcastService,
}

#[subscriptions]
impl ChatGateway {
    #[new]
    pub fn new(broadcast: RedisBroadcastService) -> Self {
        Self { broadcast }
    }

    #[subscribe_message("message")]
    async fn handle_message(
        &self,
        client: WsClient,
        message: WsMessage,
    ) -> WsHandlerResult {
        // Publish to all clients across all processes
        self.broadcast
            .to_all()
            .send(message)
            .await
            .ok();
        Ok(WsHandlerOutput::Empty)
    }
}
```

## RedisBroadcastService API

The API mirrors `BroadcastService` but all `join_room`, `leave_room`, and membership queries are async because they touch Redis:

```rust
// Targeting — returns RedisBroadcastTarget
broadcast.to_all()                          // all connected clients (all processes)
broadcast.to_room(room_name)                // clients in a named room (global via Redis sets)
broadcast.to_client(client_id)              // a specific client (routed to its process)
broadcast.except(client_id)                 // all clients except one

// Target refinement
.and_room(room)                             // add a room (to_room targets): union of members
.in_namespace(ns)                           // keep only clients in this namespace

// Sending (async, on the target builder)
.send(WsMessage) -> Result<usize, BroadcastError>    // returns Ok(0) — count unknowable at publish time
.send_event(event, data) -> Result<usize, BroadcastError>  // JSON: {"event": ..., "data": ...}

// Room membership (async — reads/writes Redis sets)
broadcast.join_room(client_id, room_id) -> Result<(), BroadcastError>
broadcast.leave_room(client_id, room_id) -> Result<(), BroadcastError>
broadcast.get_room_clients(room_id) -> Vec<String>   // async, global view
broadcast.get_client_rooms(client_id) -> Vec<String> // async, global view
```

## Rooms

Room membership is stored in Redis sets, so every process sees the same membership state. The keys and channels the module uses, for an operator reading the instance directly:

| Key | Holds |
|---|---|
| `ulo:rooms:{room}` | the client ids in that room; a client's own id doubles as its auto-room |
| `ulo:client:{id}:rooms` | the rooms one client is in |
| `ulo:client:{id}:process` | which process that client is connected to |
| `ulo:broadcast` | the Pub/Sub channel every process subscribes to — the fan-out path for `to_all`, `to_room` and `except` |
| `ulo:broadcast:{process_id}` | one process's own Pub/Sub channel; `to_client` publishes straight here when the affinity key names the process, skipping the global fan-out |



```rust
#[subscribe_message("join")]
async fn handle_join(
    &self,
    client: WsClient,
    message: WsMessage,
) -> WsHandlerResult {
    // Frame: {"event": "join", "data": {"room": "lobby"}}
    let text = message
        .as_text()
        .ok_or_else(|| WsError::InvalidMessage("Expected text message".into()))?;
    let data: serde_json::Value = serde_json::from_str(text)
        .map_err(|e| WsError::InvalidMessage(format!("Invalid JSON: {}", e)))?;
    let room = data["data"]["room"]
        .as_str()
        .ok_or_else(|| WsError::InvalidMessage("Missing room field".into()))?;

    self.broadcast.join_room(&client.id, room).await.ok();
    self.broadcast
        .to_room(room)
        .send(WsMessage::text(format!("{} joined {room}", client.id)))
        .await
        .ok();
    Ok(WsHandlerOutput::Empty)
}
```

## Differences from BroadcastModule

| | `BroadcastModule` | `RedisBroadcastModule` |
|---|---|---|
| Scope | Single process | All processes sharing a Redis instance |
| Injectable | `BroadcastService` | `RedisBroadcastService` |
| Room queries | Sync (`get_room_clients` → `Vec`) | Async (`get_room_clients` → `Vec`) |
| Send return | `Result<usize>` (actual count) | `Result<usize>` (always `Ok(0)`) |
| Dependency | None | Redis |

`BroadcastService` is still registered internally — the gateway framework uses it for connection lifecycle hooks. You inject `RedisBroadcastService` for all cross-process sends.
