title: WebSocket + Dependency Injection
description: Gateways are full DI participants — inject any service, wrap them in guards, interceptors and error handlers, use lifecycle hooks.
---

WebSocket gateways are providers like any other. They participate fully in the DI system: they can inject services, implement lifecycle hooks, and be guarded and intercepted like HTTP routes — with `WsContext` in place of `HttpContext`.

## Injecting services into gateways

Declare dependencies as `#[inject]` fields and take them in the `#[new]` constructor:

```rust
use ulo::websocket::{BroadcastModule, BroadcastService, WsClient, WsError, WsHandlerOutput, WsMessage};
use ulo::WsHandlerResult;
use ulo::{injectable, module, new, on_connect, on_disconnect, subscriptions, websocket_gateway};

#[injectable]
pub struct GameService { /* ... */ }

#[injectable]
pub struct PlayerService { /* ... */ }

#[websocket_gateway("/game")]
pub struct GameGateway {
    #[inject]
    game_service: GameService,
    #[inject]
    player_service: PlayerService,
    #[inject]
    broadcast: BroadcastService,
}

impl GameGateway {
    #[on_connect]
    async fn handle_connect(&self, client: &WsClient) -> Result<(), WsError> {
        let player = self.player_service.create_session(&client.id).await;
        self.broadcast
            .to_client(&client.id)
            .send(WsMessage::text(serde_json::to_string(&player).unwrap()))
            .await
            .ok();
        Ok(())
    }

    #[on_disconnect]
    async fn handle_disconnect(&self, client: &WsClient) {
        self.player_service.end_session(&client.id).await;
    }
}

#[subscriptions]
impl GameGateway {
    #[new]
    pub fn new(
        game_service: GameService,
        player_service: PlayerService,
        broadcast: BroadcastService,
    ) -> Self {
        Self { game_service, player_service, broadcast }
    }

    #[subscribe_message("action")]
    async fn handle_action(&self, client: WsClient, message: WsMessage) -> WsHandlerResult {
        if let Some(text) = message.as_text() {
            if let Ok(action) = serde_json::from_str::<GameAction>(text) {
                let result = self.game_service.process_action(&client.id, action).await;
                let msg = WsMessage::text(serde_json::to_string(&result).unwrap());
                return Ok(msg.into());
            }
        }
        Ok(WsHandlerOutput::Empty)
    }
}
```

What `handle_connect` establishes here lives in the injected service, keyed by client id. For state that later handlers on the same connection need — an authenticated principal, a resolved tenant — the built-in home is the connection's `Session` store: write it in `#[on_connect]` or a connect guard, read it from any handler. See [Session](/docs/websocket/gateways#session).

## Guards on gateways

A WebSocket guard is a plain `#[injectable]` provider implementing `Guard<WsContext>` — no marker macro. The role is detected from the trait impl:

```rust
use ulo::async_trait;
use ulo::context::WsContext;
use ulo::traits_helpers::Guard;
use ulo::injectable;

#[injectable]
pub struct WsAuthGuard;

#[async_trait]
impl Guard<WsContext> for WsAuthGuard {
    async fn can_activate(&self, ctx: &WsContext) -> bool {
        // Handshake header keys are stored lowercase
        ctx.client().handshake.headers.get("x-auth-token").is_some()
    }
}
```

Apply it to a gateway with `#[use_guards]` on the `#[subscriptions]` impl — this is the idiomatic form. The guard must also be listed in the module's `providers`:

```rust
#[websocket_gateway("/chat")]
pub struct ChatGateway {
    #[inject]
    broadcast: BroadcastService,
}

#[subscriptions]
#[use_guards(WsAuthGuard)]
impl ChatGateway {
    #[new]
    pub fn new(broadcast: BroadcastService) -> Self {
        Self { broadcast }
    }

    #[subscribe_message("message")]
    async fn handle_message(&self, client: WsClient, message: WsMessage) -> WsHandlerResult {
        // Only reached when WsAuthGuard passed
        Ok(WsMessage::text("ok").into())
    }
}

#[module(
    imports: [BroadcastModule::new()],
    providers: [ChatGateway, WsAuthGuard],
)]
struct ChatModule;
```

<Callout type="warn">
Gateway-level guards run twice: once at **connect** and once per **message**. A rejection at connect refuses the connection — the caller gets the canonical envelope and a close frame, see [Refusing a connection](/docs/websocket/gateways#refusing-a-connection). A rejection on a message answers the sender with the canonical `Forbidden` envelope and leaves the connection open.
</Callout>

### Per-handler guards

`#[use_guards]` also works on individual `#[subscribe_message]` methods — the guard then applies only to that event, on top of any gateway-level guards:

```rust
#[subscribe_message("admin_command")]
#[use_guards(AdminGuard)]
async fn on_admin(&self, client: WsClient, msg: WsMessage) -> WsHandlerResult {
    Ok(WsMessage::text("done").into())
}
```

A per-handler guard is keyed by its event, so it never runs at connect — a connection carries no event. Only gateway-level and global guards admit connections.

### Global WebSocket guards

Register a guard for every gateway on the factory. Global enhancers are per-transport — WebSocket guards never see HTTP traffic:

```rust
use std::sync::Arc;

let mut factory = UloFactory::new();
factory.use_global_ws_guards(Arc::new(WsAuthGuard));
let mut app = factory.create_with(ChatModule).await?;
```

Globally registered instances are constructed by you (`Arc::new`), so they don't need to appear in `providers`. A global guard is prepended to every gateway's list, which means it runs at connect as well as per message.

## Interceptors on gateways

Same model: `#[injectable]` + `Interceptor<WsContext, WsHandlerResult>`. Interceptors wrap the handler — run code before and after, or rewrite the reply. Whatever `intercept` returns is the answer:

```rust
use ulo::async_trait;
use ulo::context::WsContext;
use ulo::traits_helpers::{Interceptor, InterceptorNext};
use ulo::WsHandlerResult;
use ulo::injectable;

#[injectable]
pub struct WsLoggingInterceptor;

#[async_trait]
impl Interceptor<WsContext, WsHandlerResult> for WsLoggingInterceptor {
    async fn intercept(
        &self,
        ctx: &WsContext,
        next: Box<dyn InterceptorNext<WsContext, WsHandlerResult>>,
    ) -> WsHandlerResult {
        println!("event '{}' from {}", ctx.event(), ctx.client().id);
        let result = next.run(ctx).await;
        println!("event processed");
        result
    }
}
```

To rewrite the handler's reply, rewrite the value `next.run(ctx).await` returned:

```rust
use ulo::websocket::{WsHandlerOutput, WsMessage};

#[injectable]
pub struct WsPrefixInterceptor;

#[async_trait]
impl Interceptor<WsContext, WsHandlerResult> for WsPrefixInterceptor {
    async fn intercept(
        &self,
        ctx: &WsContext,
        next: Box<dyn InterceptorNext<WsContext, WsHandlerResult>>,
    ) -> WsHandlerResult {
        match next.run(ctx).await {
            Ok(WsHandlerOutput::Single(msg)) => {
                let prefixed = format!("prefixed:{}", msg.as_text().unwrap_or(""));
                Ok(WsMessage::text(prefixed).into())
            }
            other => other,
        }
    }
}
```

Apply with `#[use_interceptors(...)]` on the `#[subscriptions]` impl or on a single handler, or globally with `factory.use_global_ws_interceptors(Arc::new(...))`. Enhancer attributes stack:

```rust
#[subscriptions]
#[use_guards(WsAuthGuard)]
#[use_interceptors(WsLoggingInterceptor)]
impl ChatGateway {
    // ...
}
```

## Error handlers on gateways

An error handler is the same shape again: `#[injectable]` + `ErrorHandler<WsContext, WsMessage>`. Note the answer type — the chain answers with a bare `WsMessage`, not the `WsHandlerResult` an interceptor returns. Returning `None` observes the error without shaping it and passes it to the next handler in the chain:

```rust
use ulo::async_trait;
use ulo::context::WsContext;
use ulo::traits_helpers::{ChainError, ErrorHandler};
use ulo::websocket::WsMessage;
use ulo::injectable;

#[injectable]
pub struct WsErrorLogger;

#[async_trait]
impl ErrorHandler<WsContext, WsMessage> for WsErrorLogger {
    async fn handle_error(&self, error: ChainError<'_>, ctx: &WsContext) -> Option<WsMessage> {
        eprintln!("event '{}' failed: {error}", ctx.event());
        None
    }
}
```

Apply it with `#[use_error_handlers(WsErrorLogger)]` on the `#[subscriptions]` impl or on a single handler, or globally with `factory.use_global_ws_error_handler(Arc::new(WsErrorLogger))`. The chain is the only error seam on this transport: it sees handler errors and the framework's own events alike — see [Framework events](/docs/websocket/gateways#framework-events).

## WsContext

`WsContext` is the context a guard, interceptor, hook or handler receives. There is one per execution: one per message, one for the connect, and one for the disconnect.

```rust
ctx.client()        // &WsClient — id, handshake headers/query, session
ctx.session()       // &Session — the connection's store, shared by every execution on it
ctx.message()       // &WsMessage — the inbound frame
ctx.event()         // &str — the routed event name; "connect" and "disconnect" for those two
ctx.extensions()    // &Extensions — the per-execution bag; a guard inserts, the handler reads
ctx.metadata()      // Option<&Metadata> — what #[set_metadata] declared for this handler
ctx.cache()         // &ExecutionCache — one construction per execution, shared by clone
ctx.cancellation()  // &CancellationToken
ctx.deadline()      // Option<Instant> — always None here; the transport carries no deadline
```

`metadata`, `cache`, `cancellation` and `deadline` come from the `HandlerContext` trait, so `use ulo::context::HandlerContext;` has to be in scope to call them.

There is no response slot: a handler answers by returning, and an interceptor that wants a different answer returns a different value.

WebSocket request scope is per **message**, not per connection: guards, interceptors, and any request-scoped providers they depend on are rebuilt for each message, and `ctx.extensions()` empties with each. State that must survive from one message to the next belongs in `ctx.session()` — see [Session](/docs/websocket/gateways#session).

## What runs on a connect

A connect is an admission decision, not a call. Guards run, because answering admission is a guard's whole contract. Interceptors and error handlers do not: an interceptor wraps a call and its answer, an error handler shapes an answer, and a connection that is never opened has neither.

| | Connect | Message |
|---|---|---|
| Global guards | yes | yes |
| Gateway-level guards — `#[use_guards]` on the `#[subscriptions]` impl | yes | yes |
| Per-handler guards — `#[use_guards]` on one `#[subscribe_message]` | no | yes, for that event |
| Interceptors | no | yes |
| Error handlers | no | yes |

The connect has an execution of its own, whose context and extensions bag the guards share with the `#[on_connect]` hook — so what a guard writes there, the hook reads. It ends with the connect; anything the later messages need goes in the [session](/docs/websocket/gateways#session) instead.

Refusing a connection still answers the caller: the canonical envelope, then a close carrying an RFC 6455 code. See [Refusing a connection](/docs/websocket/gateways#refusing-a-connection).

## Lifecycle hooks on gateways

Gateways support the same lifecycle hooks as any provider. All hooks are `async`; the two startup hooks return `ulo::InitResult`:

```rust
#[websocket_gateway("/ticker")]
pub struct StockTickerGateway {
    #[inject]
    market_service: MarketService,
}

impl StockTickerGateway {
    #[on_module_init]
    async fn init(&self) -> ulo::InitResult {
        self.market_service.connect().await;
        Ok(())
    }

    #[on_application_shutdown]
    async fn shutdown(&self, _signal: Option<String>) {
        self.market_service.disconnect().await;
    }
}

#[subscriptions]
impl StockTickerGateway {
    #[new]
    pub fn new(market_service: MarketService) -> Self {
        Self { market_service }
    }

    #[subscribe_message("subscribe")]
    async fn handle_subscribe(&self, client: WsClient, message: WsMessage) -> WsHandlerResult {
        // handle ticker subscription...
        Ok(WsHandlerOutput::Empty)
    }
}
```

For WebSocket-specific setup after the gateway's path is registered, use `#[after_init]` — see [Gateways](/docs/websocket/gateways#connection-lifecycle-hooks).

## Module setup

```rust
#[module(
    imports: [BroadcastModule::new()],
    providers: [
        GameGateway,
        GameService,
        PlayerService,
        WsAuthGuard,
        WsLoggingInterceptor,
    ],
)]
pub struct GameModule;
```

Include `BroadcastModule::new()` in `imports` whenever any gateway or service needs `BroadcastService`, and list every enhancer referenced by `#[use_guards]` / `#[use_interceptors]` in `providers`.
