## What `toni new` generates

```
my_app/
├── Cargo.toml                 # toni, toni-axum, tokio
└── src/
    ├── main.rs                # entry point — ToniFactory + adapter
    └── app/
        ├── mod.rs             # #[path] module declarations
        ├── app.module.rs      # root module (AppModule)
        ├── app.controller.rs  # AppController — CRUD routes at /app
        └── app.service.rs     # AppService — business logic
```

The dotted file names (`app.module.rs`, NestJS-style) aren't valid Rust module names on their own, so `mod.rs` maps each file to a module with a `#[path]` attribute:

```rust title="src/app/mod.rs"
#[path = "app.module.rs"]
pub mod app_module;

#[path = "app.controller.rs"]
pub mod app_controller;

#[path = "app.service.rs"]
pub mod app_service;
```

`main.rs` then imports the root module as `app::app_module::AppModule`.

## Adding features with `generate resource`

From the project root, `toni generate resource users` creates a feature directory and wires it in:

```
src/
├── main.rs
└── app/
    ├── mod.rs                 # gains: #[path = "users/mod.rs"] pub mod users;
    ├── app.module.rs          # gains: UsersModule in imports
    ├── app.controller.rs
    ├── app.service.rs
    └── users/
        ├── mod.rs             # #[path] declarations for the three files below
        ├── users.module.rs    # UsersModule
        ├── users.controller.rs # UsersController — CRUD routes at /users
        └── users.service.rs   # UsersService
```

No manual wiring needed — the command edits `src/app/mod.rs` and adds the new module to the `imports:` list in `app.module.rs`. See [CLI Commands](/docs/cli/commands) for the generated file contents.

## One feature per module

The key organizing principle: **each feature is a module**. A module owns its controllers and services. What it needs from other modules it declares as `imports`. What it offers to other modules it declares in `exports`.

```rust
// database module
#[module(
    providers: [DatabaseService],
    exports: [DatabaseService],   // other modules can inject this
)]
pub struct DatabaseModule;

// users module
#[module(
    imports: [DatabaseModule],    // now DatabaseService is available here
    controllers: [UsersController],
    providers: [UsersService],
)]
pub struct UsersModule;
```

## Root module

The root module is the entry point for the module graph. In a larger application it typically only imports feature modules — it doesn't own controllers or services itself.

```rust
#[module(
    imports: [
        DatabaseModule,
        UsersModule,
        AuthModule,
        ProductsModule,
    ],
)]
pub struct AppModule;
```

<FromNest>
The CLI reproduces the `feature/feature.module.ts` convention with `#[path]`
attributes, which is what lets a file called `app.module.rs` resolve at all.
Nothing requires it — a hand-rolled `users_module.rs` works without the `#[path]`
indirection. `forRoot()` carries over as `for_root`: integration crates return a
`DynamicModule` that you list under `imports:`.
</FromNest>

## Shared/common code

Infrastructure that spans features — guards, interceptors, common types — belongs in a shared location (`common/` or `shared/`). Enhancers are plain structs implementing the relevant trait; the traits are generic over the transport context (`HttpContext`, `RpcContext`, `WsContext`).

```rust title="common/logging_interceptor.rs"
use toni::HttpResponse;
use toni::async_trait;
use toni::context::HttpContext;
use toni::traits_helpers::{Interceptor, InterceptorNext};

pub struct LoggingInterceptor;

#[async_trait]
impl Interceptor<HttpContext, HttpResponse> for LoggingInterceptor {
    async fn intercept(
        &self,
        ctx: &HttpContext,
        next: Box<dyn InterceptorNext<HttpContext, HttpResponse>>,
    ) -> HttpResponse {
        let req = ctx.request();
        println!("-> {} {}", req.method, req.uri);
        next.run(ctx).await
    }
}
```

Register globally on the factory, before creating the application:

```rust
use std::sync::Arc;

let mut factory = ToniFactory::new();
factory.use_global_http_interceptors(Arc::new(LoggingInterceptor));

let mut app = factory.create_with(AppModule).await.unwrap();
app.use_http_adapter(AxumAdapter::new(), ("127.0.0.1", 3000)).unwrap();
app.start().await.unwrap();
```

Global registration is per transport: `use_global_http_*`, `use_global_rpc_*`, `use_global_ws_*`, and `use_global_grpc_*`, each covering guards, interceptors, and error handlers. `use_global_middleware` carries no transport in its name because middleware is HTTP-only — it runs before routing, on every request the adapter receives.
