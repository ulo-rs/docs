Save a file, the project rebuilds, the server restarts. The CLI ships this loop as `ulo dev`; the generic Rust watch tools do the same.

## ulo dev

From the project root:

```bash
ulo dev
```

Runs `cargo run` and restarts it on every save of a `.rs` or `.toml` file, with `.gitignore` paths, `.git/`, and `target/` excluded. Which package, binary, example, and features cargo builds are selectable, as are the profile and pass-through binary arguments — see [CLI Commands](/docs/cli/commands#ulo-dev).

## watchexec

[watchexec](https://github.com/watchexec/watchexec) restarts an arbitrary command when watched files change:

```bash
cargo install watchexec-cli
```

From the project root:

```bash
watchexec -r -e rs,toml -- cargo run
```

`-r` kills and restarts the process on each change; `-e rs,toml` limits watching to Rust sources and Cargo manifests. Paths in `.gitignore` (including `target/`) are excluded automatically.

Older guides reference `cargo watch -x run` — that project is no longer maintained, and its README points to watchexec as the successor.

## bacon

[bacon](https://dystroy.org/bacon/) is a terminal UI built around compile feedback:

```bash
cargo install --locked bacon
bacon run
```

`bacon run` rebuilds and restarts the application on save. Plain `bacon` runs `cargo check` on save instead — the fastest way to see errors while editing, when you don't need the server up.

<FromNest>
`ulo dev` is the same loop as `nest start --watch`: recompile, restart. The unit
is different — TypeScript recompiles in milliseconds, a Rust incremental rebuild
takes seconds. The settings below matter here in a way they do not in Node.
</FromNest>

## Faster rebuilds

The save-to-running gap is compile plus link time. Two adjustments give most of the improvement:

**Reduce debuginfo.** Full debuginfo is the default in dev profiles and is a large share of compile and link cost. If you aren't stepping through a debugger, keep only line tables — panic backtraces stay resolvable:

```toml title="Cargo.toml"
[profile.dev]
debug = "line-tables-only"
```

**Use a faster linker.** On Linux, [mold](https://github.com/rui314/mold) cuts link time substantially:

```toml title=".cargo/config.toml"
[target.x86_64-unknown-linux-gnu]
linker = "clang"
rustflags = ["-C", "link-arg=-fuse-ld=mold"]
```

Adjust the target triple to your host. Recent macOS toolchains ship a fast linker by default.

## The restart gap

<Callout type="warn">
While a rebuild runs, the server is down — connections are refused, not queued. Scripts that poll the API during development should retry:

```bash
curl --retry 5 --retry-connrefused http://localhost:3000/users
```
</Callout>

## Keeping the port alive across restarts

The gap exists because the listening socket dies with the process. Move ownership of the socket to something that outlives the rebuild and it stops being a gap: connections wait in the kernel's accept queue and are answered when the new process starts accepting. A request made mid-rebuild sees latency instead of a refusal.

`ulo dev --listen` does exactly that: it binds the port itself and hands the same socket to every restart.

```bash
ulo dev --listen 3000
```

The application has to take that socket instead of binding its own. [listenfd](https://crates.io/crates/listenfd) reads it:

```toml title="Cargo.toml"
[dependencies]
listenfd = "1"
```

Take the inherited socket when there is one, and bind normally when there isn't — one binary then works under the watcher, under systemd, and on its own:

```rust
let mut fds = listenfd::ListenFd::from_env();
let target: ulo::BindTarget = match fds.take_tcp_listener(0)? {
    Some(listener) => listener.into(),
    None => ("127.0.0.1", 3000).into(),
};

app.use_http_adapter(AxumAdapter::new(), target)?;
```

Save a file now and the request you fire during the rebuild is answered by the new process rather than refused.

`ulo-http-rocket` is the one adapter this does not work with — Rocket binds internally from its own configuration and rejects a pre-supplied listener, failing at `app.bind()`. See the [adapter capability table](/docs/http-adapters#official-adapters).

`--listen` needs file-descriptor passing and is therefore Unix-only. [systemfd](https://crates.io/crates/systemfd) is the cross-platform alternative and works with any watcher, including plain `bacon` or `cargo watch`:

```bash
systemfd --no-pid -s http::3000 -- bacon run
```

The mechanism behind both is systemd's socket activation protocol, so the same adoption code gives zero-downtime restarts under systemd with nothing added — [Production deployment](/docs/deployment/production) covers that side.
