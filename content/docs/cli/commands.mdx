The CLI has three commands: `ulo new`, `ulo generate resource`, and `ulo dev`.

## ulo new

Create a new Ulo project from a starter template.

```bash
ulo new <project-name>
```

The project name may contain only alphanumerics, `-`, and `_`. The command fails if a directory with that name already exists.

**Example:**

```bash
ulo new my_api
# ✅ Successfully created project 'my_api'!
#
# Next steps:
#   cd my_api
#   cargo build
```

Generated layout:

```
my_api/
├── Cargo.toml
└── src/
    ├── main.rs
    └── app/
        ├── mod.rs
        ├── app.module.rs
        ├── app.controller.rs
        └── app.service.rs
```

`Cargo.toml` pins `ulo = "0.2.0"`, `ulo-http-axum = "0.1.0"`, and `tokio` with full features. The generated `main.rs`:

```rust
use app::app_module::AppModule;
use ulo::UloFactory;
use ulo_http_axum::AxumAdapter;

mod app;

#[tokio::main]
async fn main() {
    let mut app = UloFactory::new()
        .create_with(AppModule)
        .await.unwrap();

    app.use_http_adapter(AxumAdapter::new(), ("127.0.0.1", 3000))
        .unwrap();

    app.start().await.unwrap();
}
```

`AppController` serves `POST`/`GET`/`PUT`/`DELETE` at `http://127.0.0.1:3000/app`, each delegating to a matching `AppService` method. The dotted file names are mapped to Rust modules with `#[path]` attributes in `src/app/mod.rs` — see [Project Structure](/docs/getting-started/project-structure).

## ulo generate resource

Generate a CRUD resource — module, controller, and service — and wire it into the application.

```bash
ulo generate resource <name>
```

Run it from the project root (the command edits files under `src/app/`). `resource` is the only generator type; there are no separate `module`/`controller`/`service` generators.

**Example:**

```bash
ulo generate resource users
```

Creates `src/app/users/`:

```
src/app/users/
├── mod.rs                  # #[path] declarations for the files below
├── users.module.rs         # UsersModule
├── users.controller.rs     # UsersController
└── users.service.rs        # UsersService
```

and wires it in automatically:

- `src/app/mod.rs` gains `#[path = "users/mod.rs"] pub mod users;`
- `src/app/app.module.rs` gains the import and `UsersModule` in its `imports:` list

Type names are the input name with the first letter uppercased (`users` → `UsersModule`, `UsersController`, `UsersService`); module and file names are snake_cased.

### Generated controller

```rust
use super::users_service::UsersService;
use ulo::extractors::Path;
use ulo::*;

#[controller("/users")]
pub struct UsersController {
    #[inject]
    users_service: UsersService,
}

#[routes]
impl UsersController {
    #[post("/")]
    fn create(&self) -> Body {
        Body::text(self.users_service.create())
    }

    #[get("/")]
    fn find_all(&self) -> Body {
        Body::text(self.users_service.find_all())
    }

    #[get("/{id}")]
    fn find_by_id(&self, Path(id): Path<String>) -> Body {
        Body::text(self.users_service.find_by_id(id))
    }

    #[put("/")]
    fn update(&self) -> Body {
        Body::text(self.users_service.update())
    }

    #[delete("/")]
    fn delete(&self) -> Body {
        Body::text(self.users_service.delete())
    }
}
```

### Generated service

```rust
use ulo::*;

#[injectable]
pub struct UsersService;

impl UsersService {
    pub fn find_all(&self) -> String {
        "find_all".to_string()
    }

    pub fn find_by_id(&self, id: String) -> String {
        format!("find_by_id {}", id)
    }

    pub fn create(&self) -> String {
        "create".to_string()
    }

    pub fn update(&self) -> String {
        "update".to_string()
    }

    pub fn delete(&self) -> String {
        "delete".to_string()
    }
}
```

### Generated module

```rust
use ulo::*;

use super::users_controller::UsersController;
use super::users_service::UsersService;

#[module(
  imports: [],
  controllers: [UsersController],
  providers: [UsersService],
  exports: []
)]
impl UsersModule {}
```

The stub methods return placeholder strings — replace them with real logic and typed responses (see [Quick Start](/docs/getting-started/quick-start)).

## ulo dev

Run the application and restart it whenever a source file changes.

```bash
ulo dev
```

Run it from the project root. On start it runs `cargo run`; on every save of a `.rs` or `.toml` file it rebuilds and restarts the process. Changes are throttled at 250ms, so a burst of saves triggers one rebuild. Paths in `.gitignore` (plus `target/` and `.git/`) are excluded from watching. Ctrl-C stops the watcher and the application.

A restart sends SIGTERM and waits two seconds before SIGKILL. A generated app has no signal handlers and exits at once; an app that wires [`shutdown_handle()`](/docs/techniques/graceful-shutdown) gets that window to drain.

```
[ulo dev] watching /path/to/my_api — running `cargo run` (Ctrl-C to stop)
   Compiling my_api v0.1.0
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 2.31s
     Running `target/debug/my_api`
...
[ulo dev] change detected, restarting
```

If a rebuild fails, the compile errors are printed and the previous process stays down; the next save triggers another attempt.

**Options:**

- `--release` — build and run in release mode
- `-p, --package <SPEC>` — package to run, for a workspace with more than one
- `--bin <NAME>` — run this binary instead of the package default
- `--example <NAME>` — run this example instead of a binary
- `-F, --features <FEATURES>` — features to activate; repeat the flag or comma-separate the list
- `--all-features` — activate every feature of every selected package
- `--no-default-features` — do not activate the `default` feature
- `--cargo-arg <ARG>` — forward one argument to cargo as given, for a flag this list does not mirror; repeat it once per argument
- `--listen <ADDR>` — hold the listening socket across restarts (Unix only)
- `-- <args>` — everything after `--` is passed to the application binary

```bash
ulo dev --release -- --config config/local.toml
```

### Choosing what cargo builds

Cargo stops reading its own flags at the `--`, so a target or feature selector belongs before it:

```bash
ulo dev -p my-api --example demo -F tls -- --config config/local.toml
```

`--bin` and `--example` are refused together — a run has one target.

Flags outside that list go through `--cargo-arg`, one argument per occurrence:

```bash
ulo dev --cargo-arg --offline --cargo-arg --timings
```

The cargo command is assembled in a fixed order: `run`, `--release`, the target selector (`--package`/`--bin`/`--example`), `--features`, `--all-features`, `--no-default-features`, the `--cargo-arg` values in the order given, then `--` and the application arguments.

### Surviving the rebuild gap

By default the server is down while a rebuild runs, and connections are refused until the new process binds. `--listen` closes that gap: the socket is bound once by the watcher and passed to every restart, so requests arriving mid-rebuild wait in the kernel accept queue and are answered by the new process instead of failing.

```bash
ulo dev --listen 3000
# [ulo dev] holding 127.0.0.1:3000 — passing it to each restart
```

A bare port means localhost; pass `host:port` to bind elsewhere. The socket is announced through the systemd socket-activation variables (`LISTEN_FDS`), so the application has to adopt it rather than bind its own:

```rust
use listenfd::ListenFd;

let mut fds = ListenFd::from_env();
let target: BindTarget = match fds.take_tcp_listener(0)? {
    Some(listener) => listener.into(),
    None => ("127.0.0.1", 3000).into(),
};
app.use_http_adapter(AxumAdapter::new(), target)?;
```

Keep the fallback branch — it is what lets the binary still run on its own, outside the watcher. An application that binds its own address while `--listen` holds it fails at startup with "address in use". See [Bind Targets](/docs/techniques/bind-targets) for the full listener API, and the `socket_activation` example for a running version.

The same code path serves systemd socket activation in production, which uses the same protocol.

<Callout type="warn">
Rocket is the exception: it binds through its own configuration and refuses a pre-bound listener, so `--listen` does not work with `ulo-http-rocket`.
</Callout>
