title: SeaORM
description: Integrating SeaORM with Ulo's module system for managed database connections.
---

`ulo-db-seaorm` provides a `SeaOrmModule` that connects to a database at startup and makes `DatabaseConnection` available to any provider in the application via the global DI scope.

`for_root` is called once, in the root module. Feature modules inject `DatabaseConnection` without importing `SeaOrmModule` themselves.

## Setup

Add the dependency:

```toml title="Cargo.toml"
[dependencies]
ulo = "0.2"
ulo-db-seaorm = "0.1"
sea-orm = { version = "1", features = ["sqlx-postgres", "runtime-tokio-rustls"] }
```

## Registration

Call `SeaOrmModule::for_root` in your root module's `imports`:

```rust
use ulo_db_seaorm::SeaOrmModule;

#[module(
    imports: [
        SeaOrmModule::for_root("postgres://user:pass@localhost/mydb"),
    ],
    controllers: [UsersController],
    providers: [UsersService],
)]
pub struct AppModule;
```

`for_root` returns a **global** `CheckedModule` — a `DynamicModule` carrying a configurable startup check. It works anywhere a module does: as an import or as the root module.

The connection object itself is constructed lazily, without dialing. What verifies the database is the [startup check](#startup-check): it probes the server in `on_module_init`, so a bad URL or unreachable host surfaces as `Err(StartupError::HookFailed)` from `UloFactory::create` — naming the module, with any password in the connection URL redacted (`postgres://user:***@localhost/mydb`) — rather than on the first query.

## Startup check

By default the module confirms the database answers before the application starts: 3 attempts, 2 seconds apart, each bounded to 5 seconds — worst case ≈ 19 s. Tune the schedule with `with_startup_check`:

```rust
use ulo::StartupCheck;

SeaOrmModule::for_root(url)
    .with_startup_check(StartupCheck::default().attempts(5))
```

`StartupCheck` builders: `.attempts(u32)`, `.delay(Duration)`, `.timeout(Duration)`.

Opt out with `.without_startup_check()` — the application then starts without contacting the database, and failures surface where the connection is first used. Worth taking when a readiness probe already reports the database and the application should stay up while it recovers.

A named connection (see below) runs the same check and reports failures under its name.

## Injecting the connection

The default connection is injected by type — no token string needed:

```rust
use sea_orm::DatabaseConnection;

#[injectable]
pub struct UsersService {
    #[inject]
    db: DatabaseConnection,
}

impl UsersService {
    pub async fn find_all(&self) -> Result<Vec<user::Model>, sea_orm::DbErr> {
        user::Entity::find().all(&self.db).await
    }

    pub async fn find_by_id(&self, id: i32) -> Result<Option<user::Model>, sea_orm::DbErr> {
        user::Entity::find_by_id(id).one(&self.db).await
    }
}
```

`DatabaseConnection` is `Clone` — it wraps a connection pool internally. Each inject gets a clone that shares the same pool.

## Multiple connections

`for_root_named` registers an additional connection under a string name:

```rust
#[module(
    imports: [
        SeaOrmModule::for_root("postgres://localhost/app"),
        SeaOrmModule::for_root_named("analytics", "postgres://localhost/analytics"),
    ],
)]
pub struct AppModule;
```

A named connection is injected by its name token:

```rust
#[injectable]
pub struct ReportsService {
    #[inject]
    db: DatabaseConnection,          // default connection
    #[inject("analytics")]
    analytics: DatabaseConnection,   // named connection
}
```

Names are global identifiers — two connections cannot share one, even across different integration crates. Two unnamed `for_root` calls with different URLs are refused at startup (one would shadow the other with no error), so every connection past the first needs a name. A named connection registers the connection only; the `health` feature's indicator stays on the default `for_root` connection.

## Using env vars

Combine with `ulo-config` or `std::env::var` to avoid hardcoding credentials:

```rust
#[module(
    imports: [
        SeaOrmModule::for_root(std::env::var("DATABASE_URL").expect("DATABASE_URL must be set")),
    ],
)]
pub struct AppModule;
```

Or with a typed config. A module is not a provider — it can't be produced by a factory at injection time, so the URL must be known when the module tree is built. Load the config first, then pass the value to `for_root`:

```rust
use ulo_config::{Config, ConfigModule};

#[derive(Config, Clone)]
pub struct AppConfig {
    #[env("DATABASE_URL")]
    pub database_url: String,
}

fn database_module() -> ulo::CheckedModule {
    let config = ConfigModule::<AppConfig>::from_env()
        .expect("invalid configuration");
    SeaOrmModule::for_root(config.get_ref().database_url.clone())
}

#[module(
    imports: [database_module()],
)]
pub struct AppModule;
```

## Shutdown

`SeaOrmModule` closes the database connection gracefully when `app.close()` is called or the application shuts down. In-flight queries are allowed to complete before the connection is closed.

## Health checks

Enable the `health` feature to have `for_root` also register a `SeaOrmHealthIndicator`, which exposes `ping_check(key)` for use with `ulo-health`. The indicator shares the registered connection — enabling `health` opens no second pool — and resolves it lazily on each check. See [Health checks](/docs/techniques/health).

## API reference

```rust
use ulo_db_seaorm::SeaOrmModule;

SeaOrmModule::for_root(url: impl Into<String>) -> CheckedModule
SeaOrmModule::for_root_named(name: impl Into<String>, url: impl Into<String>) -> CheckedModule
```

The returned `CheckedModule`:
- has identity base `SeaOrmModule`, fingerprinted by the connection URL; the rendered key is `SeaOrmModule#<16 hex digits>`, which is what startup errors print and what `get_module_by_id` accepts
- provides `sea_orm::DatabaseConnection` — by type for `for_root`, under the `name` token for `for_root_named`
- exports `DatabaseConnection`
- is **global** (no need to import into feature modules)
- carries the startup check — reconfigure with `.with_startup_check(StartupCheck)`, drop it with `.without_startup_check()`
