---
title: SQLx
description: Integrating SQLx with Toni's module system for compile-time checked SQL queries.
---

`toni-sqlx` provides a `SqlxModule` with database-specific constructors that connect a connection pool at startup and make it available application-wide.

There is no ORM layer over the pool: queries stay SQL strings, and SQLx's `query!` macros check them against a live database at compile time.

## Setup

Add the dependency with the appropriate features for your database and TLS runtime:

```toml title="Cargo.toml"
[dependencies]
toni = "0.2"
toni-sqlx = { version = "0.1", features = ["postgres", "runtime-tokio-rustls"] }
sqlx = { version = "0.8", features = ["postgres", "runtime-tokio-rustls", "macros"] }
```

Available database features: `postgres`, `mysql`, `sqlite`.  
Available runtime features: `runtime-tokio-rustls`, `runtime-tokio-native-tls`.

## Registration

Use the database-specific constructor in your root module's `imports`:

```rust
use toni_sqlx::SqlxModule;

// PostgreSQL
#[module(
    imports: [
        SqlxModule::postgres("postgresql://user:pass@localhost/mydb"),
    ],
    controllers: [UsersController],
    providers: [UsersService],
)]
pub struct AppModule;
```

```rust
// MySQL
SqlxModule::mysql("mysql://user:pass@localhost/mydb")

// SQLite
SqlxModule::sqlite("sqlite:./data.db")
```

Each constructor returns a **global** `CheckedModule` — a `DynamicModule` carrying a configurable startup check. It works anywhere a module does: as an import or as the root module.

The pool itself is constructed lazily, without dialing. What verifies the database is the [startup check](#startup-check): it probes the server in `on_module_init`, so a bad URL or unreachable host surfaces as `Err(StartupError::HookFailed)` from `ToniFactory::create` — naming the module, with any password in the connection URL redacted (`postgresql://user:***@localhost/mydb`) — rather than on the first query.

## Startup check

By default the module confirms the database answers before the application starts: 3 attempts, 2 seconds apart, each bounded to 5 seconds — worst case ≈ 19 s. Tune the schedule with `with_startup_check`:

```rust
use toni::StartupCheck;

SqlxModule::postgres(url)
    .with_startup_check(StartupCheck::default().attempts(5))
```

`StartupCheck` builders: `.attempts(u32)`, `.delay(Duration)`, `.timeout(Duration)`.

Opt out with `.without_startup_check()` — the application then starts without contacting the database, and failures surface where the pool is first used. Worth taking when a readiness probe already reports the database and the application should stay up while it recovers.

A named pool (see below) runs the same check and reports failures under its name.

## Injecting the pool

The injected type depends on the database:
- `sqlx::Pool<Postgres>` for PostgreSQL
- `sqlx::Pool<MySql>` for MySQL
- `sqlx::Pool<Sqlite>` for SQLite

```rust
use sqlx::PgPool; // also available as toni_sqlx::PgPool

#[injectable]
pub struct UsersService {
    #[inject]
    pool: PgPool,
}

impl UsersService {
    pub async fn find_all(&self) -> sqlx::Result<Vec<User>> {
        sqlx::query_as!(User, "SELECT id, name, email FROM users")
            .fetch_all(&self.pool)
            .await
    }

    pub async fn create(&self, name: &str, email: &str) -> sqlx::Result<i32> {
        let row = sqlx::query!(
            "INSERT INTO users (name, email) VALUES ($1, $2) RETURNING id",
            name,
            email,
        )
        .fetch_one(&self.pool)
        .await?;
        Ok(row.id)
    }
}
```

`PgPool` is `Clone` — all clones share the same pool.

## Multiple pools

Each constructor has a `_named` variant that registers an additional pool under a string name:

```rust
#[module(
    imports: [
        SqlxModule::postgres("postgresql://localhost/app"),
        SqlxModule::postgres_named("analytics", "postgresql://localhost/analytics"),
    ],
)]
pub struct AppModule;
```

```rust
#[injectable]
pub struct ReportsService {
    #[inject]
    pool: PgPool,             // default pool
    #[inject("analytics")]
    analytics: PgPool,        // named pool
}
```

Names are global identifiers — two connections cannot share one, even across different integration crates. Two unnamed constructor calls with different URLs are refused at startup (one would shadow the other with no error), so every pool past the first needs a name. A named pool registers the pool only; the `health` feature's indicator stays on the default constructor's pool.

## Using env vars

```rust
#[module(
    imports: [
        SqlxModule::postgres(
            std::env::var("DATABASE_URL").expect("DATABASE_URL must be set")
        ),
    ],
)]
pub struct AppModule;
```

## Shutdown

`SqlxModule` calls `pool.close().await` when `app.close()` is called. In-flight queries are allowed to complete before the pool is closed.

## Health checks

Enable the `health` feature to have each constructor also register a `SqlxHealthIndicator<DB>` (aliased per database as `PostgresHealthIndicator`, `MySqlHealthIndicator`, `SqliteHealthIndicator`), which exposes `ping_check(key)` for use with `toni-terminus`. The indicator shares the registered pool — enabling `health` opens no second one — and resolves it lazily on each check. See [Health checks](/docs/techniques/health).

## API reference

```rust
use toni_sqlx::SqlxModule;

SqlxModule::postgres(url: impl Into<String>) -> CheckedModule
SqlxModule::mysql(url: impl Into<String>)    -> CheckedModule
SqlxModule::sqlite(url: impl Into<String>)   -> CheckedModule

SqlxModule::postgres_named(name: impl Into<String>, url: impl Into<String>) -> CheckedModule
SqlxModule::mysql_named(name: impl Into<String>, url: impl Into<String>)    -> CheckedModule
SqlxModule::sqlite_named(name: impl Into<String>, url: impl Into<String>)   -> CheckedModule
```

Each constructor is gated behind its database feature (`postgres`, `mysql`, `sqlite`).

Each returned `CheckedModule`:
- provides the database-specific `Pool<DB>` type — by type for the default constructors, under the `name` token for the `_named` variants
- exports the pool
- is **global** (no need to import into feature modules)
- carries the startup check — reconfigure with `.with_startup_check(StartupCheck)`, drop it with `.without_startup_check()`

Re-exports available from `toni_sqlx` (feature-gated):
- `PgPool` — `sqlx::Pool<Postgres>` (feature: `postgres`)
- `MySqlPool` — `sqlx::Pool<MySql>` (feature: `mysql`)
- `SqlitePool` — `sqlx::Pool<Sqlite>` (feature: `sqlite`)
- `SqlxError`, `Row`, `query`, `query_as`
