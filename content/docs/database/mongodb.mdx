---
title: MongoDB
description: Integrating MongoDB with Toni's module system via the managed Database handle.
---

`toni-mongodb` provides a `MongoModule` that connects to MongoDB at startup and makes `mongodb::Database` available application-wide via the global DI scope.

`for_root` is called once, in the root module. Feature modules inject `Database` without importing `MongoModule` themselves.

## Setup

Add the dependency:

```toml title="Cargo.toml"
[dependencies]
toni = "0.2"
toni-mongodb = "0.1"
mongodb = "3"
```

## Registration

Call `MongoModule::for_root` with the MongoDB URI and database name:

```rust
use toni_mongodb::MongoModule;

#[module(
    imports: [
        MongoModule::for_root("mongodb://localhost:27017", "mydb"),
    ],
    controllers: [UsersController],
    providers: [UsersService],
)]
pub struct AppModule;
```

`for_root` returns a **global** `CheckedModule` — a `DynamicModule` carrying a configurable startup check. It works anywhere a module does: as an import or as the root module.

The client itself is constructed lazily, without dialing. What verifies the server is the [startup check](#startup-check): it probes MongoDB in `on_module_init`, so an unreachable host surfaces as `Err(StartupError::HookFailed)` from `ToniFactory::create` — naming the module, with any password in the URI redacted (`mongodb://user:***@host:27017`) — rather than on the first query.

## Startup check

By default the module confirms MongoDB answers before the application starts: 3 attempts, 2 seconds apart, each bounded to 5 seconds — worst case ≈ 19 s. Tune the schedule with `with_startup_check`:

```rust
use toni::StartupCheck;

MongoModule::for_root(uri, "mydb")
    .with_startup_check(StartupCheck::default().attempts(5))
```

`StartupCheck` builders: `.attempts(u32)`, `.delay(Duration)`, `.timeout(Duration)`.

Opt out with `.without_startup_check()` — the application then starts without contacting MongoDB, and failures surface where the database handle is first used. Worth taking when a readiness probe already reports the database and the application should stay up while it recovers.

A named connection (see below) runs the same check and reports failures under its name.

## Injecting the database

The default connection's `Database` is injected by type — no token string needed:

```rust
use mongodb::{Database, Collection, bson::doc};
use serde::{Deserialize, Serialize};

#[derive(Debug, Serialize, Deserialize)]
pub struct User {
    #[serde(rename = "_id", skip_serializing_if = "Option::is_none")]
    pub id: Option<mongodb::bson::oid::ObjectId>,
    pub name: String,
    pub email: String,
}

#[injectable]
pub struct UsersService {
    #[inject]
    db: Database,
}

impl UsersService {
    fn collection(&self) -> Collection<User> {
        self.db.collection("users")
    }

    pub async fn find_all(&self) -> mongodb::error::Result<Vec<User>> {
        use futures::StreamExt;
        let cursor = self.collection().find(doc! {}).await?;
        cursor.collect::<Vec<_>>().await.into_iter().collect()
    }

    pub async fn create(&self, name: String, email: String) -> mongodb::error::Result<String> {
        let user = User { id: None, name, email };
        let result = self.collection().insert_one(user).await?;
        Ok(result.inserted_id.to_string())
    }
}
```

`Database` is `Clone` — all clones share the same connection pool managed by the underlying `Client`.

## Multiple connections

`for_root_named` registers an additional connection under a string name. The name is the **first** argument, ahead of the URI and database name:

```rust
#[module(
    imports: [
        MongoModule::for_root("mongodb://localhost:27017", "app"),
        MongoModule::for_root_named("analytics", "mongodb://localhost:27017", "analytics"),
    ],
)]
pub struct AppModule;
```

```rust
#[injectable]
pub struct ReportsService {
    #[inject]
    db: Database,             // default connection
    #[inject("analytics")]
    analytics: Database,      // named connection
}
```

Names are global identifiers — two connections cannot share one, even across different integration crates. Two unnamed `for_root` calls with different config are refused at startup (one would shadow the other with no error), so every connection past the first needs a name. A named connection registers the database handle only; the `health` feature's indicator stays on the default `for_root` connection.

## Using env vars

```rust
#[module(
    imports: [
        MongoModule::for_root(
            std::env::var("MONGO_URI").expect("MONGO_URI must be set"),
            std::env::var("MONGO_DB").unwrap_or_else(|_| "myapp".to_string()),
        ),
    ],
)]
pub struct AppModule;
```

## Shutdown

`MongoModule` calls `client.shutdown().await` when `app.close()` is called, allowing in-flight operations to complete before the connection pool is drained.

## Health checks

Enable the `health` feature to have `for_root` also register a `MongoHealthIndicator`, which exposes `ping_check(key)` for use with `toni-terminus`. The indicator shares the registered database handle — enabling `health` opens no second client — and resolves it lazily on each check. See [Health checks](/docs/techniques/health).

## API reference

```rust
use toni_mongodb::MongoModule;

MongoModule::for_root(
    uri: impl Into<String>,
    db_name: impl Into<String>,
) -> CheckedModule

MongoModule::for_root_named(
    name: impl Into<String>,
    uri: impl Into<String>,
    db_name: impl Into<String>,
) -> CheckedModule
```

The returned `CheckedModule`:
- has identity base `MongoModule`, fingerprinted by the URI and database name; the rendered key is `MongoModule#<16 hex digits>`, which is what startup errors print and what `get_module_by_id` accepts
- provides `mongodb::Database` — by type for `for_root`, under the `name` token for `for_root_named`
- exports `Database`
- is **global** (no need to import into feature modules)
- carries the startup check — reconfigure with `.with_startup_check(StartupCheck)`, drop it with `.without_startup_check()`

Re-exports available from `toni_mongodb`:
- `mongodb::Collection`
- `mongodb::Database`
- `mongodb::bson::Document`
- `mongodb::bson::doc` (macro)
- `mongodb::bson::oid::ObjectId`
- `mongodb::error::Error as MongoError`
- `mongodb::options::FindOptions`
