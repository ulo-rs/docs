---
title: Redis
description: Integrating Redis with Ulo's module system via the managed ConnectionManager.
---

`ulo-db-redis` provides a `RedisModule` that opens a managed Redis connection at startup and makes `redis::aio::ConnectionManager` available application-wide.

## Setup

Add the dependency:

```toml title="Cargo.toml"
[dependencies]
ulo = "0.2"
ulo-db-redis = "0.1"
redis = { version = "1", features = ["tokio-comp", "connection-manager"] }
```

## Registration

Call `RedisModule::for_root` in your root module's `imports`:

```rust
use ulo_db_redis::RedisModule;

#[module(
    imports: [
        RedisModule::for_root("redis://127.0.0.1:6379"),
    ],
    controllers: [CacheController],
    providers: [CacheService],
)]
pub struct AppModule;
```

`for_root` returns a **global** `CheckedModule` — a `DynamicModule` carrying a configurable startup check. It works anywhere a module does: as an import or as the root module.

The `ConnectionManager` itself is constructed lazily, without dialing. What verifies the server is the [startup check](#startup-check): it probes Redis in `on_module_init`, so an invalid URL or an unreachable server surfaces as `Err(StartupError::HookFailed)` from `UloFactory::create` — naming the module, with any password in the connection URL redacted (`redis://user:***@host:6379`) — rather than on the first command.

## Startup check

By default the module confirms Redis answers before the application starts: 3 attempts, 2 seconds apart, each bounded to 5 seconds — worst case ≈ 19 s. Tune the schedule with `with_startup_check`:

```rust
use ulo::StartupCheck;

RedisModule::for_root(url)
    .with_startup_check(StartupCheck::default().attempts(5))
```

`StartupCheck` builders: `.attempts(u32)`, `.delay(Duration)`, `.timeout(Duration)`.

Opt out with `.without_startup_check()` — the application then starts without contacting Redis, and failures surface where the connection is first used. Worth taking when a readiness probe already reports Redis and the application should stay up while it recovers.

A named connection (see below) runs the same check and reports failures under its name.

## Injecting the connection

The default connection's `ConnectionManager` is injected by type:

```rust
use redis::aio::ConnectionManager;
use redis::AsyncCommands;

#[injectable]
pub struct CacheService {
    #[inject]
    redis: ConnectionManager,
}

impl CacheService {
    pub async fn get(&self, key: &str) -> redis::RedisResult<Option<String>> {
        let mut conn = self.redis.clone();
        conn.get(key).await
    }

    pub async fn set(&self, key: &str, value: &str, ttl_secs: u64) -> redis::RedisResult<()> {
        let mut conn = self.redis.clone();
        conn.set_ex(key, value, ttl_secs).await
    }

    pub async fn del(&self, key: &str) -> redis::RedisResult<()> {
        let mut conn = self.redis.clone();
        conn.del(key).await
    }
}
```

`ConnectionManager` is `Clone` — all clones share the same underlying multiplexed connection. Clone it before calling async commands (the `AsyncCommands` trait requires `&mut self` on the connection handle).

## Multiple connections

`for_root_named` registers an additional connection under a string name, injected via its name token:

```rust
#[module(
    imports: [
        RedisModule::for_root("redis://127.0.0.1:6379"),
        RedisModule::for_root_named("cache", "redis://10.0.0.5:6379"),
    ],
)]
pub struct AppModule;
```

```rust
#[injectable]
pub struct CacheService {
    #[inject]
    redis: ConnectionManager,        // default connection
    #[inject("cache")]
    cache: ConnectionManager,        // named connection
}
```

Names are global identifiers — two connections cannot share one, even across different integration crates. Two unnamed `for_root` calls with different URLs are refused at startup (one would shadow the other with no error), so every connection past the first needs a name. A named connection registers the connection only; the `health` feature's indicator stays on the default `for_root` connection.

## Using env vars

```rust
#[module(
    imports: [
        RedisModule::for_root(
            std::env::var("REDIS_URL").unwrap_or_else(|_| "redis://127.0.0.1:6379".to_string())
        ),
    ],
)]
pub struct AppModule;
```

## Shutdown

`RedisModule` registers no shutdown hook. The `ConnectionManager` closes by being dropped, along with the last clone of it held anywhere in the application. Nothing waits for a command in flight.

## Health checks

Enable the `health` feature to have `for_root` also register a `RedisHealthIndicator`, which exposes `ping_check(key)` for use with `ulo-health`. The indicator shares the registered connection — enabling `health` opens no second client — and resolves it lazily on each check. See [Health checks](/docs/techniques/health).

## API reference

```rust
use ulo_db_redis::RedisModule;

RedisModule::for_root(url: impl Into<String>) -> CheckedModule
RedisModule::for_root_named(name: impl Into<String>, url: impl Into<String>) -> CheckedModule
```

The returned `CheckedModule`:
- has identity base `RedisModule`, fingerprinted by the connection URL; the rendered key is `RedisModule#<16 hex digits>`, which is what startup errors print and what `get_module_by_id` accepts
- provides `redis::aio::ConnectionManager` — by type for `for_root`, under the `name` token for `for_root_named`
- exports `ConnectionManager`
- is **global** (no need to import into feature modules)
- carries the startup check — reconfigure with `.with_startup_check(StartupCheck)`, drop it with `.without_startup_check()`
