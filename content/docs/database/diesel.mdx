`ulo-db-diesel` provides a `DieselModule` with database-specific constructors that set up an async connection pool (via `deadpool`) at startup and make it available application-wide.

Queries are validated against your schema at compile time, and `diesel-async` runs them without blocking the executor.

## Setup

Add the dependency with the appropriate feature for your database:

```toml title="Cargo.toml"
[dependencies]
ulo = "0.2"
ulo-db-diesel = { version = "0.1", features = ["postgres"] }
diesel = { version = "2", features = ["postgres_backend"], default-features = false }
diesel-async = { version = "0.8", features = ["postgres", "deadpool"] }
```

Available features: `postgres`, `mysql`.

## Registration

Use the database-specific constructor in your root module's `imports`:

```rust
use ulo_db_diesel::DieselModule;

// PostgreSQL
#[module(
    imports: [
        DieselModule::postgres("postgresql://user:pass@localhost/mydb"),
    ],
    controllers: [UsersController],
    providers: [UsersService],
)]
pub struct AppModule;
```

```rust
// MySQL
DieselModule::mysql("mysql://user:pass@localhost/mydb")
```

Each constructor returns a **global** `CheckedModule` — a `DynamicModule` carrying a configurable startup check. It works anywhere a module does: as an import or as the root module.

The pool itself is constructed lazily, without dialing. What verifies the database is the [startup check](#startup-check): it probes the server in `on_module_init`, so an unreachable host surfaces as `Err(StartupError::HookFailed)` from `UloFactory::create` — naming the module, with any password in the connection URL redacted (`postgresql://user:***@localhost/mydb`) — rather than on the first query.

## Startup check

By default the module confirms the database answers before the application starts: 3 attempts, 2 seconds apart. Tune the schedule with `with_startup_check`:

```rust
use ulo::StartupCheck;

DieselModule::postgres(url)
    .with_startup_check(StartupCheck::default().attempts(5))
```

`StartupCheck` builders: `.attempts(u32)`, `.delay(Duration)`, `.timeout(Duration)`.

`.attempts` and `.delay` apply here. `.timeout` does not: deadpool answers a failed create rather than retrying it, so an attempt is bounded by the connection attempt the driver makes, and against a host that drops packets rather than refusing it, one attempt can outlast the whole schedule.

Opt out with `.without_startup_check()` — the application then starts without contacting the database, and failures surface where the pool is first used. Worth taking when a readiness probe already reports the database and the application should stay up while it recovers.

A named pool (see below) runs the same check and reports failures under its name.

## Injecting the pool

The injected type is a `deadpool::Pool` over the async connection type:
- `diesel_async::pooled_connection::deadpool::Pool<AsyncPgConnection>` for PostgreSQL
- `diesel_async::pooled_connection::deadpool::Pool<AsyncMysqlConnection>` for MySQL

```rust
use ulo_db_diesel::PgPool; // re-exported from ulo_db_diesel
use diesel::prelude::*;
use diesel_async::RunQueryDsl;

#[injectable]
pub struct UsersService {
    #[inject]
    pool: PgPool,
}

impl UsersService {
    pub async fn find_all(&self) -> Result<Vec<User>, diesel::result::Error> {
        let mut conn = self.pool.get().await
            .map_err(|_| diesel::result::Error::DatabaseError(
                diesel::result::DatabaseErrorKind::UnableToSendCommand,
                Box::new("pool error".to_string()),
            ))?;

        users::table.load::<User>(&mut conn).await
    }

    pub async fn create(&self, new_user: NewUser) -> Result<User, diesel::result::Error> {
        let mut conn = self.pool.get().await.unwrap();
        diesel::insert_into(users::table)
            .values(&new_user)
            .get_result(&mut conn)
            .await
    }
}
```

Obtain a connection from the pool with `.get().await` for each operation. The pool manages the connection lifecycle.

## Multiple pools

Each constructor has a `_named` variant that registers an additional pool under a string name:

```rust
#[module(
    imports: [
        DieselModule::postgres("postgresql://localhost/app"),
        DieselModule::postgres_named("analytics", "postgresql://localhost/analytics"),
    ],
)]
pub struct AppModule;
```

```rust
#[injectable]
pub struct ReportsService {
    #[inject]
    pool: PgPool,             // default pool
    #[inject("analytics")]
    analytics: PgPool,        // named pool
}
```

Names are global identifiers — two connections cannot share one, even across different integration crates. Two unnamed constructor calls with different URLs are refused at startup (one would shadow the other with no error), so every pool past the first needs a name. A named pool registers the pool only; the `health` feature's indicator stays on the default constructor's pool.

## Using env vars

```rust
#[module(
    imports: [
        DieselModule::postgres(
            std::env::var("DATABASE_URL").expect("DATABASE_URL must be set")
        ),
    ],
)]
pub struct AppModule;
```

## Shutdown

`DieselModule` calls `pool.close()` when `app.close()` is called, draining the connection pool.

## Health checks

Enable the `health` feature to have each constructor also register a health indicator: `PgHealthIndicator` for PostgreSQL, `MySqlHealthIndicator` for MySQL. Both expose `ping_check(key)` for use with `ulo-health`. The indicator shares the registered pool and resolves it lazily on each check; enabling `health` opens no second pool. See [Health checks](/docs/techniques/health).

## API reference

```rust
use ulo_db_diesel::DieselModule;

DieselModule::postgres(url: impl Into<String>) -> CheckedModule
DieselModule::mysql(url: impl Into<String>)    -> CheckedModule

DieselModule::postgres_named(name: impl Into<String>, url: impl Into<String>) -> CheckedModule
DieselModule::mysql_named(name: impl Into<String>, url: impl Into<String>)    -> CheckedModule
```

Each constructor is gated behind its database feature (`postgres`, `mysql`).

Each returned `CheckedModule`:
- provides the database-specific `deadpool::Pool<Connection>` type — by type for the default constructors, under the `name` token for the `_named` variants
- exports the pool
- is **global** (no need to import into feature modules)
- carries the startup check — reconfigure with `.with_startup_check(StartupCheck)`, drop it with `.without_startup_check()`

Re-exports available from `ulo_db_diesel` (feature-gated):
- `PgPool` — `deadpool::Pool<AsyncPgConnection>` (feature: `postgres`)
- `MySqlPool` — `deadpool::Pool<AsyncMysqlConnection>` (feature: `mysql`)
- `AsyncPgConnection`, `AsyncMysqlConnection`
- `diesel::prelude` as `prelude`
- `DieselError`
- `RunQueryDsl`
