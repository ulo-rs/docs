## TcpAdapter

Server-side RPC transport. Accepts inbound connections on a TCP port and dispatches newline-delimited JSON frames to registered RPC controllers.

```rust
use toni_tcp::TcpAdapter;

TcpAdapter::new(host: impl Into<String>, port: u16) -> TcpAdapter
TcpAdapter::from_listener(listener: std::net::TcpListener) -> TcpAdapter
TcpAdapter::new(...).with_drain_timeout(impl Into<Option<Duration>>) -> TcpAdapter  // default: 10 s
TcpAdapter::new(...).with_max_inflight(max: usize) -> TcpAdapter                    // default: unbounded
```

- `from_listener` — serve on a socket the caller already bound and put into listening state instead of binding one (systemd socket activation, inherited descriptors via `listenfd`); see [Bind targets](/docs/techniques/bind-targets).
- `with_drain_timeout` — how long `close()` waits for in-flight requests before aborting them; `None` waits without bound.
- `with_max_inflight` — caps concurrently running handler tasks across all connections. Over-cap request-response messages are rejected with an `"overloaded"` error frame; fire-and-forget messages are dropped with a log line.

Register after `ToniFactory::create`:

```rust
let mut app = ToniFactory::create(AppModule).await.unwrap();
app.use_rpc_adapter(TcpAdapter::new("0.0.0.0", 4000)).unwrap();
app.start().await.unwrap();
```

The listener binds synchronously during pattern registration, so a port conflict surfaces as `Err` from `app.bind()` / `app.start()` rather than a panic in the accept loop.

## TcpClientTransport

Client-side transport for `RpcClient`. Maintains a single persistent TCP connection with lazy connect and correlation-id-based request tracking.

```rust
use toni_tcp::TcpClientTransport;

TcpClientTransport::new(host: impl Into<String>, port: u16) -> TcpClientTransport
TcpClientTransport::new(...).with_timeout(Duration) -> TcpClientTransport  // default: 5 s
```

`with_timeout` means two things depending on the call. On `send` it bounds the whole request-response round trip. On a streaming call it bounds the gap to the next frame, the first frame included; expiry arrives as an `Err(RpcClientError::Timeout)` item and sends the cancel frame.

Wrap in `RpcClient` and register as a provider:

```rust
provider_value!(
    "ORDERS_CLIENT",
    RpcClient::new(TcpClientTransport::new("127.0.0.1", 4000))
)
```

After a fatal transport error (reader-loop exit, write failure) the cached connection is dropped and the next call reconnects. Requests pending at the moment of failure fail with `RpcClientError::Transport("connection closed")`.

The transport implements the full `RpcClientTransport` surface, streaming included:

```rust
open_stream(pattern: &str, data: RpcData, metadata: HashMap<String, String>)
    -> Result<RpcReplyStream, RpcClientError>
```

`RpcClient::stream` / `RpcRequest::stream` call it. The returned `RpcReplyStream` yields `Result<RpcData, RpcClientError>` until the server's end marker; dropping it before that sends the call's cancel frame, so the server aborts the call and the handler's execution hears its cancellation token. A `send()` that receives a stream frame fails with `RpcClientError::Transport("streaming reply to a single-reply call — use stream()")`.

Attach per-call headers via the request builder; they travel as the `metadata` field on the wire frame:

```rust
client.request("order.create")
    .header("trace-id", trace_id)
    .send(RpcData::json(payload))
    .await?;
```

### Wire protocol

Newline-delimited JSON (`\n` terminated). A request payload and a single reply cannot carry binary on the TCP wire — use base64 or another encoding inside a JSON string. A binary *stream item* is the exception: it travels base64-encoded under the `stream_b64` key.

**Request-response inbound** (`metadata` optional; string values surface as handler headers via `ctx.headers()`):
```json
{"pattern": "order.create", "data": {...}, "id": "1", "metadata": {"trace-id": "abc"}}
```

**Response:**
```json
{"id": "1", "response": {...}}
```

**Domain error** — a handler returning a type implementing `toni::Error` produces a wire-success frame carrying the canonical error envelope, not a wire error:
```json
{"id": "1", "response": {"status": "error", "kind": "NotFound", "message": "...", "details": {...}}}
```

**Recovered panic** — a panic in a guard, an interceptor or the handler body is caught and answered on the same lane as any other error the pipeline produced:
```json
{"id": "1", "response": {"status": "error", "kind": "Internal", "message": "panic recovered in handler: ..."}}
```

**Framework error** — the wire-error frame is written when dispatch itself failed and there is no handler answer to render: an unrouted pattern (`not_found`), a guard rejection no error handler claimed (`forbidden`), an interceptor returning an `Err` of its own (`error`), or a backpressure rejection (`overloaded`). A handler's own `RpcError::Internal` is not on this lane.
```json
{"id": "1", "err": {"message": "...", "status": "not_found"}}
```

**Stream frames** — a streaming reply is item frames closed by an end marker, every frame carrying the call's `id`:
```json
{"id": "1", "stream": {...}}
{"id": "1", "stream_b64": "AAEC"}
{"id": "1", "end": true}
{"id": "1", "end": true, "err": {"message": "...", "status": "error"}}
```

The caller cancels an in-flight call with `{"id": "1", "cancel": true}` on the same connection; a dropped connection cancels everything it still had in flight.

**Fire-and-forget inbound (no `id`):**
```json
{"pattern": "order.shipped", "data": {...}}
```

An `#[event_pattern]` handler reached with an `id` gets a `{"id": "1", "response": null}` ack so the caller's pending request closes instead of timing out.
