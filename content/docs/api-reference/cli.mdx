## Installation

```bash
cargo install ulo-cli
```

## Commands

### ulo new

```
ulo new <project-name>
```

Scaffolds a new Ulo project:

```
<project-name>/
├── Cargo.toml                 # ulo 0.2.0, ulo-http-axum 0.1.0, tokio
└── src/
    ├── main.rs                # UloFactory + AxumAdapter on 127.0.0.1:3000
    └── app/
        ├── mod.rs             # #[path]-based module declarations
        ├── app.module.rs      # AppModule wiring AppController + AppService
        ├── app.controller.rs  # #[controller("/app")] with CRUD routes
        └── app.service.rs     # #[injectable] AppService
```

Project names may contain only alphanumerics, `-`, and `_`. The target directory must not already exist.

### ulo generate resource

```
ulo generate resource <name>
```

Run from the project root. Creates `src/app/<name>/`:

```
src/app/<name>/
├── mod.rs
├── <name>.module.rs      # <Name>Module
├── <name>.controller.rs  # #[controller("/<name>")] with CRUD routes + GET /{id}
└── <name>.service.rs     # #[injectable] <Name>Service
```

The resource is wired in automatically: `<Name>Module` is added to the `imports` list in `src/app/app.module.rs`, and the new directory is declared in `src/app/mod.rs`.

`resource` is the only generate type.

### ulo dev

```
ulo dev [OPTIONS] [-- <args>...]
```

Runs `cargo run` and restarts the application whenever a `.rs` or `.toml` file changes (250 ms throttle). The watch excludes `.gitignore` paths, `**/target/**`, and `**/.git/**`. On restart the old process gets SIGTERM, then SIGKILL after a 2 s grace.

| Flag | Effect |
|------|--------|
| `--listen <ADDR>` | Bind the socket once in the watcher and pass it to every restart via the `LISTEN_FDS` protocol; a bare port means localhost. Unix only; not supported with `ulo-http-rocket` |
| `--release` | Build and run in release mode |
| `-p, --package <SPEC>` | Package to run, for a workspace with more than one |
| `--bin <NAME>` | Run this binary instead of the package default |
| `--example <NAME>` | Run this example instead of a binary (refused together with `--bin`) |
| `-F, --features <FEATURES>` | Features to activate; repeat the flag or comma-separate the list |
| `--all-features` | Activate every feature of every selected package |
| `--no-default-features` | Do not activate the `default` feature |
| `--cargo-arg <ARG>` | Forward one argument to cargo as given; repeat once per argument |
| `-- <args>` | Everything after `--` is passed to the application binary |

The cargo command is assembled as `run`, `--release`, the target selector, `--features`, `--all-features`, `--no-default-features`, the `--cargo-arg` values in order, then `--` and the application arguments.

The command sits behind ulo-cli's default-on `dev` cargo feature; installing with `cargo install ulo-cli --no-default-features` omits it. See [CLI Commands](/docs/cli/commands) for the dev-loop walkthrough.

## Version

```bash
ulo --version   # prints the installed ulo-cli crate version
ulo --help
```
