## GrpcAdapter

The crate's only adapter type. It drives a [tonic](https://docs.rs/tonic) server through the application's bind / serve / drain lifecycle; services declared with `#[controller]` + `#[grpc_methods]` are discovered through DI and wrapped with the enhancer pipeline before tonic sees them.

```rust
use ulo_grpc::GrpcAdapter;

GrpcAdapter::new(addr: SocketAddr) -> GrpcAdapter
GrpcAdapter::from_listener(listener: std::net::TcpListener) -> GrpcAdapter

adapter.add_service(svc) -> GrpcAdapter                                  // a tonic service, as-is
adapter.with_drain_timeout(impl Into<Option<Duration>>) -> GrpcAdapter   // default: 10 s
adapter.with_max_inflight(impl Into<Option<usize>>) -> GrpcAdapter       // default: unbounded
adapter.with_max_per_connection(impl Into<Option<usize>>) -> GrpcAdapter // default: unbounded
adapter.with_tls(config: tonic::transport::ServerTlsConfig) -> GrpcAdapter
```

Register it after `UloFactory::create`, and run under a `LocalSet` — the application is `!Send`:

```rust
let addr: SocketAddr = "127.0.0.1:50051".parse()?;
let mut app = UloFactory::create(AppModule).await?;
app.use_grpc_adapter(GrpcAdapter::new(addr))?;
app.start().await?;
```

Port `0` asks the OS for a free port; `BoundAdapters::grpc` reports what it assigned. `from_listener` serves on a socket the caller already bound and put into listening state — a supervisor holding it across restarts leaves requests queued in the accept backlog rather than refused. See [Bind targets](/docs/techniques/bind-targets).

### add_service

Takes any tonic-generated service handle — a `*Server::new(handler)` value — and mounts it beside the DI-registered ones. Services added this way go straight to tonic: no guards, no interceptors, no error handlers, no panic recovery. Reflection and health are ordinary services and arrive this way too, `tonic-reflection` and `tonic-health` being dependencies of your crate rather than of this one.

### Concurrency caps

`with_max_inflight` bounds concurrent handlers across the whole server; `with_max_per_connection` bounds them per connection, so one client opening many parallel streams cannot monopolise a server that is under its global cap. Both shed rather than queue: over the cap, a call is rejected with `ResourceExhausted`. They stack.

### Drain

`with_drain_timeout` sets how long `close()` waits for in-flight calls, streams included, before ending them. Each ends with `UNAVAILABLE`, and a streaming handler's cancellation token fires as its reply ends. Closing is bounded by the same timer, so `close()` returns within twice what is set here. `None` waits without bound.

### TLS

`with_tls` takes `tonic::transport::ServerTlsConfig` as it is — where certificates come from, how they rotate, and whether client certificates are demanded are deployment questions, and mTLS is `ServerTlsConfig::client_ca_root`. The acceptor is built during `app.bind()`, so a certificate the process cannot read is a `StartupError::Adapter` rather than a surprise on the first connection.

It needs a crypto provider, which is a cargo feature — the same choice tonic asks for:

```toml title="Cargo.toml"
ulo-grpc = { version = "0.1", features = ["tls-ring"] }   # or "tls-aws-lc"
```

With both enabled, tonic resolves to ring. These are the crate's only features.

## to_status

```rust
pub fn to_status<E: ulo::Error>(error: E) -> tonic::Status
```

Maps a domain error to a `tonic::Status` by its `kind()`, the way every transport renders one, and keeps the error on the status's source slot.

A `#[grpc_methods]` handler returns its error and the generated method does this itself. What is left for this function is a service written against tonic's own trait and registered through `add_service`, outside the framework's dispatch — the orphan rule stops `ulo` implementing `From<E>` into a foreign type, so the hop is written where both types are reachable:

```rust
let order = self.orders.create(request.into_inner()).map_err(ulo_grpc::to_status)?;
```

For a bare `?`, give the error type the impl in the crate that owns it:

```rust
impl From<OrderError> for tonic::Status {
    fn from(e: OrderError) -> Self {
        ulo_grpc::to_status(e)
    }
}
```

## GrpcRequest

```rust
pub struct GrpcRequest<T>(pub tonic::Request<T>);

request.into_inner() -> tonic::Request<T>
// Deref / DerefMut to tonic::Request<T>
```

A handler parameter: the whole request as tonic decoded it — the metadata map with its binary entries, the extensions, the peer — for a handler that wants the wire's own view rather than the context's. `HttpRequest` is the same idea on HTTP.

It declares `CONSUMES`, like `Payload<T>` and `Inbound<T>`, and the request is taken once: two of the three in one handler fail to compile naming both. It reads only a method whose caller sends one message; a streamed request is read as `Inbound<T>` with `&GrpcContext` beside it.

## MethodShape

```rust
pub trait MethodShape {
    /// What `tonic::Request<_>` carries: the message, or `tonic::Streaming<Message>`
    /// where the caller streams.
    type Arg: Send + 'static;

    /// Hand the request to the execution, where the handler's parameters take it.
    fn install(request: tonic::Request<Self::Arg>, ctx: &GrpcContext);
}
```

Implemented by the marker types [`ulo-build`](#ulo-build) writes, one per proto method. `#[grpc_methods]` names each generated signature's request type by projecting through the marker — `<greeter_ulo::Greet as MethodShape>::Arg` — because a macro runs before name resolution and cannot resolve a type it reads off a handler. The same marker installs the request on the execution, which is what makes every handler parameter an ordinary `FromContext<GrpcContext>`.

`ulo_grpc::shape` also exports the two installers a marker's `install` body calls: `message` for a method whose caller sends one message, `stream` for one whose caller streams.

## ulo-build

The build-script half. A crate writing `#[grpc_methods]` needs it as a build-dependency:

```toml title="Cargo.toml"
[build-dependencies]
ulo-build = "0.1"
tonic-prost-build = "0.14"
```

```rust
pub fn shapes(package: &str) -> Result<(), Error>
pub fn shapes_in_file(path: impl AsRef<Path>) -> Result<(), Error>
pub fn companion(source: &str) -> Result<String, Error>
```

`shapes` takes the string `tonic::include_proto!` takes, finds `$OUT_DIR/{package}.rs`, and rewrites it in place with a `{service}_toni` module of `MethodShape` markers beside the `{service}_server` module tonic wrote. `shapes_in_file` takes the path directly, for a trait tonic did not write — hand-written, or built through `tonic_build::manual`. `companion` returns the modules as a string and touches no file.

A second run replaces its own section rather than appending another, so a rebuild is idempotent. `Error` is `NoOutDir` (not running under cargo), `Io`, `Parse` (the file is not Rust tonic wrote), or `NoService` (nothing in the file declares a trait whose methods take a `Request<_>` — usually the step ran before tonic's).

The ordering and the `protoc` requirement are in the [quick start](/docs/grpc/quick-start).
