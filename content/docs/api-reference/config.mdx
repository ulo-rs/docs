## Config derive macro

`#[env]` and `#[default]` are separate attributes, one per line. A field with `#[default]` falls back to the given expression when the env var is unset; a field without it is required and fails loading when missing. Fields without `#[env]` read the SCREAMING_SNAKE_CASE of the field name.

```rust
use ulo_config::Config;

#[derive(Config, Clone)]
pub struct AppConfig {
    // Required — loading fails if DATABASE_URL is not set
    #[env("DATABASE_URL")]
    pub database_url: String,

    // Optional with a typed default expression
    #[env("PORT")]
    #[default(3000u16)]
    pub port: u16,

    // No #[env] — reads LOG_LEVEL (field name uppercased)
    #[default("info".to_string())]
    pub log_level: String,

    // Option<T> — None when the env var is missing
    #[env("REDIS_URL")]
    pub redis_url: Option<String>,

    // Nested config struct, loaded recursively
    #[nested]
    pub auth: AuthConfig,
}
```

| Attribute | Effect |
|-----------|--------|
| `#[env("VAR")]` | Read from `VAR` instead of the uppercased field name |
| `#[default(expr)]` | Typed fallback expression used when the env var is unset |
| `#[nested]` | Load the field's own `Config` struct recursively |

Default expressions are typed — use suffixed literals (`3000u16`) or explicit conversions (`"info".to_string()`).

## ConfigModule&lt;T&gt;

Loads the config eagerly and registers `ConfigService<T>` with the DI system. Import an instance in a module:

```rust
#[module(
    imports: [ConfigModule::<AppConfig>::from_env().unwrap()],
    controllers: [ConfigController],
    providers: [AppService],
)]
impl AppModule {}
```

```rust
ConfigModule::<T>::new() -> Self                                       // panics on failure
ConfigModule::<T>::from_env() -> Result<Self, ConfigError>
ConfigModule::<T>::from_file(path: impl Into<PathBuf>) -> Result<Self, ConfigError>
ConfigModule::<T>::from_env_file(env: Environment) -> Result<Self, ConfigError>

module.get() -> T        // clones the config
module.get_ref() -> &T
```

- `new()` loads from the environment and panics if loading or validation fails, with a message naming the config type — the process still stops before serving anything, but an embedding process or a test can catch the unwind. The `from_*` constructors return `Result` instead.
- `from_file(path)` loads the given `.env` file, then reads the environment.
- `from_env_file(Environment::Production)` loads `.env.production`; `Environment::Custom(name)` loads `.env.<name>`.
- `.env` file loading is built in — the crate has no Cargo features.

`ConfigModule<T>` is a module in its own right: its identity is `ModuleIdentity::of_type::<Self>()`, so two imports of the same `T` dedup into one, and modules over two different `T` stay distinct and each register their own `ConfigService`.

## ConfigService&lt;T&gt;

Injectable accessor, registered and exported automatically by `ConfigModule<T>`:

```rust
#[injectable]
pub struct AppService {
    #[inject]
    config: ConfigService<AppConfig>,
}

impl AppService {
    pub fn database_url(&self) -> &str {
        &self.config.get_ref().database_url
    }
}
```

```rust
ConfigService::new(config: Arc<T>) -> ConfigService<T>   // for tests and hand-built containers

service.get() -> T        // clones the config
service.get_ref() -> &T   // zero-copy
```

`get()` needs a type annotation on the binding (`let cfg: AppConfig = self.config.get();`) — returning it directly from a method without one causes lifetime errors. Prefer `get_ref()` when a reference suffices.

## Environment

```rust
pub enum Environment {
    Development,
    Production,
    Test,
    Custom(String),
}

Environment::from_str(s: &str) -> Self   // "dev"/"development", "prod"/"production", "test"; anything else → Custom
Environment::current() -> Self           // reads NODE_ENV, then APP_ENV; defaults to Development
```

## Validation

Opt-in per field via the `validator` crate — there is no Cargo feature. Derive `Validate` alongside `Config` and mark fields with `#[validate(...)]`; the attribute presence is the gate. Validation runs when the config loads, before the app starts. A config without `#[validate]` attrs never references `validator`.

```toml title="Cargo.toml"
[dependencies]
ulo-config = "0.1"
validator = { version = "0.20", features = ["derive"] }
```

```rust
use ulo_config::Config;
use validator::Validate;

#[derive(Config, Validate, Clone)]
pub struct AppConfig {
    #[env("DATABASE_URL")]
    #[validate(url)]
    pub database_url: String,

    #[env("PORT")]
    #[default(8080u16)]
    #[validate(range(min = 1024, max = 65535))]
    pub port: u16,
}
```

## Traits

```rust
pub trait FromEnv: Sized {
    fn load_from_env() -> Result<Self, ConfigError>;
}

pub trait Validate {
    fn validate(&self) -> Result<(), ConfigError>;
}

pub trait Config: FromEnv + Validate + Clone + Send + Sync + 'static {}
```

`#[derive(Config)]` writes the first two. `Config` itself is a blanket impl over anything satisfying its bounds, so nothing implements it directly — a type that derives the macro and is `Clone + Send + Sync` is already a `Config`, and that is the bound `ConfigModule<T>` and `ConfigService<T>` ask for.

`Validate` here is the crate's own, not `validator`'s: the derive's implementation calls `validator::Validate` where the struct carries `#[validate(...)]` attributes, and does nothing where it does not.

## ConfigError

```rust
pub enum ConfigError {
    MissingEnvVar(String),                        // required field's env var not set
    ParseError { key: String, message: String },  // env var set but not parseable as the field type
    ValidationError(String),                      // a #[validate] rule failed
    DotenvError(dotenv::Error),                   // .env file could not be loaded
    MultipleErrors(Vec<String>),
}
```
