---
title: Guards
description: Guards run before route handlers and decide whether the request is authorized to proceed.
---

A guard is a type that implements the `Guard<C>` trait. It has a single method, `can_activate`, which returns `true` to allow the request through or `false` to block it. Guards run after middleware, before interceptors and the handler.

`C` is the per-request context type — `HttpContext`, `RpcContext`, `WsContext`, or `GrpcContext`. A guard implemented for `Guard<HttpContext>` runs on HTTP routes; the same struct can implement the trait for other contexts to run on those transports too.

## The Guard trait

```rust
use ulo::async_trait;
use ulo::context::HandlerContext;

#[async_trait]
pub trait Guard<C: ?Sized + HandlerContext>: Send + Sync {
    async fn can_activate(&self, context: &C) -> bool;
}
```

Import it from `ulo::traits_helpers::Guard`. The context is a shared reference — guards read the request, metadata, and extensions. A guard can still attach values for downstream enhancers and the handler: `Extensions` mutates through `&self`.

## A simple authentication guard

```rust
use ulo::async_trait;
use ulo::context::HttpContext;
use ulo::traits_helpers::Guard;

pub struct AuthGuard;

#[async_trait]
impl Guard<HttpContext> for AuthGuard {
    async fn can_activate(&self, ctx: &HttpContext) -> bool {
        ctx.request()
            .headers
            .get("authorization")
            .and_then(|v| v.to_str().ok())
            .and_then(|h| h.strip_prefix("Bearer "))
            .map_or(false, |t| !t.is_empty())
    }
}
```

`ctx.request()` returns a `&RequestPart` (an alias for `http::request::Parts`) with `method`, `uri`, `headers`, and `extensions` fields.

## Role-based guard with metadata

Guards can read metadata attached to routes with `#[set_metadata]`. Metadata is any `Clone + Send + Sync + 'static` type, retrieved by type via `metadata()`:

```rust
use ulo::async_trait;
use ulo::context::{HandlerContext, HttpContext};
use ulo::traits_helpers::Guard;

/// Required roles to access a route.
#[derive(Clone)]
pub struct Roles(pub &'static [&'static str]);

/// Marks a route as publicly accessible.
#[derive(Clone)]
pub struct Public;

pub struct RolesGuard;

#[async_trait]
impl Guard<HttpContext> for RolesGuard {
    async fn can_activate(&self, context: &HttpContext) -> bool {
        let Some(metadata) = context.metadata() else {
            return true;
        };

        if metadata.get::<Public>().is_some() {
            return true;
        }

        let Some(Roles(required)) = metadata.get::<Roles>() else {
            return true; // no role metadata = open route
        };

        let user_role = context
            .request()
            .headers
            .get("x-user-role")
            .and_then(|v| v.to_str().ok())
            .unwrap_or("guest");

        required.iter().any(|&r| r == user_role)
    }
}
```

Attach metadata to routes:

```rust
#[controller("/api")]
pub struct ApiController {}

#[routes]
#[use_guards(RolesGuard {})]
impl ApiController {
    #[set_metadata(Public)]
    #[get("/health")]
    fn health(&self) -> Body {
        Body::json(serde_json::json!({ "status": "ok" }))
    }

    #[set_metadata(Roles(&["admin"]))]
    #[get("/admin/stats")]
    fn admin_stats(&self) -> Body {
        Body::json(serde_json::json!({ "total_users": 1000 }))
    }
}
```

`#[set_metadata]` also goes on the `#[routes]` impl block, applying to every handler in it. Repeated declarations of the same type are all kept: `get` returns the most specific one (the handler's, where both declare it), and `get_all::<T>()` returns every declaration, least-specific first.

## DI-aware guards

Guards that need services are declared as `#[injectable]` providers and implement `Guard<C>` — no marker attribute. The framework detects the role from the trait impl:

```rust
use ulo::async_trait;
use ulo::context::HttpContext;
use ulo::injectable;
use ulo::traits_helpers::Guard;

#[injectable]
pub struct JwtGuard {
    #[inject]
    auth_service: AuthService,
}

impl JwtGuard {
    #[new]
    pub fn new(auth_service: AuthService) -> Self {
        Self { auth_service }
    }
}

#[async_trait]
impl Guard<HttpContext> for JwtGuard {
    async fn can_activate(&self, ctx: &HttpContext) -> bool {
        let token = ctx
            .request()
            .headers
            .get("authorization")
            .and_then(|v| v.to_str().ok())
            .and_then(|h| h.strip_prefix("Bearer "));

        match token {
            Some(t) => self.auth_service.verify_jwt(t).await,
            None => false,
        }
    }
}
```

Register in the module's `providers` and apply by bare type name — the instance is resolved from the DI container:

```rust
#[module(
    controllers: [ProtectedController],
    providers: [JwtGuard, AuthService],
)]
pub struct AppModule;
```

```rust
#[routes]
#[use_guards(JwtGuard)]   // bare name → resolved from DI
impl ProtectedController { /* ... */ }
```

Guards without dependencies can skip DI entirely and be applied as instantiation expressions: `#[use_guards(AuthGuard {})]` or `#[use_guards(RateLimitGuard::new(100))]`.

## Applying guards

### Controller level

`#[use_guards]` goes on the `#[routes]` impl block, and applies to every handler in it:

```rust
#[controller("/admin")]
pub struct AdminController {}

#[routes]
#[use_guards(AuthGuard {}, RolesGuard {})]
impl AdminController {
    // all routes here require auth + role
}
```

### Method level

```rust
#[controller("/posts")]
pub struct PostsController {}

#[routes]
impl PostsController {
    #[get("")]
    fn find_all(&self) -> Body { /* public */ }

    #[use_guards(AuthGuard {})]   // only this route requires auth
    #[delete("/{id}")]
    fn remove(&self) -> Body { /* protected */ }
}
```

### Global (per transport)

Global registration is per-transport on `UloFactory`:

```rust
use std::sync::Arc;
use ulo::UloFactory;

let mut factory = UloFactory::new();
factory.use_global_http_guards(Arc::new(AuthGuard));

let mut app = factory.create_with(AppModule).await?;
app.use_http_adapter(AxumAdapter::new(), ("127.0.0.1", 3000))?;
app.start().await?;
```

`use_global_rpc_guards`, `use_global_ws_guards`, and `use_global_grpc_guards` are the counterparts for the other three transports; each takes an `Arc<dyn Guard<C>>` for the matching context.

Guards run in scope order — global, then controller, then method — and within each scope in the order listed. The first `false` stops the chain; remaining guards and the handler are skipped.

## Guards on other transports

The same `#[use_guards]` attribute works on `#[patterns]` impls (RPC controllers) and `#[subscriptions]` impls (WebSocket gateways), and on `#[grpc_methods]` impls for gRPC services. A single struct can serve several transports by implementing `Guard<C>` once per context:

```rust
#[injectable]
pub struct UniversalAuthGuard {}
impl UniversalAuthGuard {}

#[async_trait]
impl Guard<HttpContext> for UniversalAuthGuard {
    async fn can_activate(&self, ctx: &HttpContext) -> bool {
        ctx.request()
            .headers
            .get("authorization")
            .and_then(|v| v.to_str().ok())
            .and_then(|h| h.strip_prefix("Bearer "))
            .map_or(false, |t| t == "valid-secret")
    }
}

#[async_trait]
impl Guard<RpcContext> for UniversalAuthGuard {
    async fn can_activate(&self, ctx: &RpcContext) -> bool {
        ctx.data()
            .as_json()
            .and_then(|v| v.get("auth").and_then(|a| a.as_str()))
            .map_or(false, |t| t == "valid-secret")
    }
}

#[async_trait]
impl Guard<WsContext> for UniversalAuthGuard {
    async fn can_activate(&self, ctx: &WsContext) -> bool {
        ctx.client()
            .handshake
            .query
            .get("token")
            .map_or(false, |t| t == "valid-secret")
    }
}
```

Each `impl` is the registration for that transport. Attaching a guard to a transport whose context it doesn't implement is a type error.

### On a WebSocket connect

A gateway's guards run at two moments: once when a client connects, and again for every message that client sends. The connect pass runs guards and nothing else — no interceptors, no error handlers. A connect is an admission decision rather than a call: there is no answer to wrap or reshape, and refusing one is answered by not opening the connection.

A `false` on connect refuses the upgrade. The handshake has already completed by then, so there is no HTTP status left to refuse with and the frames are the only way the caller learns why: the canonical envelope as a text frame, then a close. A guard refusal closes with 1008 (Policy Violation); a connect hook that returns a domain error whose kind is `TooManyRequests` closes with 1013 (Try Again Later), and a server-side fault — a panicking connect guard among them — closes with 1011 (Internal Error).

The connect guards and the `#[on_connect]` hook share one context, and the client's `Session` exists before either runs. A guard that authenticates at connect writes the result to `ctx.session()`, and every later execution on that connection reads it back rather than repeating the work — `ctx.event()` is `"connect"` on the admission pass and the message's event name afterwards.

For a subprotocol that defines its own refusal code, return `WsError::Refused { code, reason }` from the connect hook. It closes with that code and puts nothing else on the wire — a client that has not agreed on the grammar cannot read an envelope written in it. This is what graphql-ws's 4406 needs:

```rust
#[on_connect]
async fn handle_connect(&self, client: &WsClient) -> Result<(), WsError> {
    let protocol = client
        .handshake
        .headers
        .get("sec-websocket-protocol")
        .map(|s| s.as_str());

    if protocol != Some("graphql-transport-ws") {
        return Err(WsError::Refused {
            code: 4406,
            reason: "Subprotocol not acceptable".into(),
        });
    }
    Ok(())
}
```

A `false` on a *message* is a different decision, because the socket is open and there is somewhere to answer. It goes through the error chain like every other transport's rejection, and the connection stays usable.

## Passing data from a guard to the handler

The extension bag is a shared handle that mutates through `&self`, so a guard can attach values for anything that runs after it:

```rust
#[derive(Clone)]
pub struct Principal {
    pub user: String,
    pub roles: Vec<String>,
}

#[async_trait]
impl Guard<HttpContext> for AuthGuard {
    async fn can_activate(&self, ctx: &HttpContext) -> bool {
        ctx.extensions().insert(Principal {
            user: "alice".into(),
            roles: vec!["admin".into()],
        });
        true
    }
}
```

Downstream enhancers retrieve the value by type:

```rust
#[async_trait]
impl Guard<HttpContext> for RequireAdminGuard {
    async fn can_activate(&self, ctx: &HttpContext) -> bool {
        match ctx.extensions().get::<Principal>() {
            Some(principal) => principal.roles.iter().any(|r| r == "admin"),
            None => false,
        }
    }
}
```

The handler reads the same bag by taking `Extensions` as a parameter — `get` returns a clone:

```rust
async fn me(&self, ext: Extensions) -> Body {
    let principal = ext.get::<Principal>().unwrap();
    Body::json(serde_json::json!({ "user": principal.user }))
}
```


## What happens when a guard blocks

Guards cannot throw or set a response — `can_activate` returns only `bool`. When it returns `false`, the framework raises a `GuardRejection` event and offers it to the error handler chain. If nothing claims it, each transport renders its own refusal:

| Transport | Unclaimed rejection |
|---|---|
| HTTP | `403` with the canonical envelope, `{ "statusCode": 403, "message": "Forbidden", "error": "Forbidden" }` |
| RPC | a wire error frame, `{"err":{"message":"...","status":"forbidden"}}` |
| WebSocket message | the canonical envelope as a text frame; the connection stays open |
| gRPC | status `PermissionDenied` |

A WebSocket *connect* is the exception, described above: the refusal closes the connection and no chain runs.

A panic inside a guard is a bug rather than a verdict, and the framework treats it as one. The panic is caught, boxed as `PanicRecovered { during: PipelineSegment::Guard }`, and offered to the same chain — `#[catch(PanicRecovered)]` claims it. Unclaimed, it renders `Internal` on all four transports: a 500 envelope on HTTP, the `Internal` envelope on RPC and WebSocket, status `Internal` on gRPC. The caller is told the server broke, not that its credentials were refused.

To send a different status or body, register an error handler for the event with `#[catch(GuardRejection)]`:

```rust
use serde_json::json;
use ulo::{catch, Error};
use ulo::context::HttpContext;
use ulo::HttpResponse;

#[catch(ulo::errors::GuardRejection)]
async fn auth_failure(err: &ulo::errors::GuardRejection, _ctx: &HttpContext) -> HttpResponse {
    HttpResponse::builder()
        .status(ulo::errors::http_status(err.kind()))
        .json(json!({
            "error": "auth_required",
            "hint": "Send `x-auth-token: <token>`",
            "detail": err.message(),
        }))
        .build()
}
```

```rust
#[routes]
#[use_guards(AuthGuard {})]
#[use_error_handlers(auth_failure {})]
impl AdminController { /* ... */ }
```

The context parameter picks the transport, and the return type follows from it: a catcher on `&HttpContext` returns `HttpResponse`, on `&RpcContext` `RpcData`, on `&WsContext` `WsMessage`, on `&GrpcContext` `GrpcStatus`.

`GuardRejection` carries `guard_index` (the position of the rejecting guard in the resolved chain) and an optional `reason`. See [Error Handling](/docs/request-lifecycle/error-handling) for the full error pipeline.
