title: Middleware
description: Request/response interception around the HTTP pipeline — logging, auth headers, rate limiting, Tower layers.
---

Middleware intercepts an HTTP request before it reaches the controller pipeline. Each middleware receives a `NextHandle` carrying the in-flight request: read it, pass it downstream with `next.run()`, replace it with `next.run_with(new_req)`, or return a response directly to short-circuit.

Middleware runs at two positions:

- **Global middleware** (`factory.use_global_middleware`) wraps the adapter's routing itself — it runs on every request, including 404s, 405s, and same-port WebSocket upgrades. Because it runs before routing, a request replaced via `next.run_with(new_req)` changes which route matches, and returning a response directly answers the request before routing happens at all — this is how the built-in [`CorsMiddleware`](/docs/techniques/cors) answers preflight.
- **Module-scoped middleware** (`configure_middleware`) is matched to routes by path pattern and runs after routing, before guards and interceptors.

## The Middleware trait

```rust
use ulo::async_trait;
use ulo::middleware::{Middleware, MiddlewareResult, NextHandle};

#[async_trait]
pub trait Middleware: Send + Sync {
    async fn handle(&self, next: NextHandle) -> MiddlewareResult;
}
```

`MiddlewareResult` is `Result<HttpResponse, Box<dyn std::error::Error + Send + Sync>>`.

`NextHandle` owns the request and the rest of the chain:

| Method | Purpose |
|--------|---------|
| `next.request()` | `&HttpRequest` — read method, URI, headers |
| `next.request_mut()` | `&mut HttpRequest` — mutate in place |
| `next.run().await` | Pass the request downstream unchanged |
| `next.run_with(req).await` | Pass a replacement request downstream |

`HttpRequest` dereferences to `http::Request<RequestBody>`, so `next.request().method()`, `.uri()`, `.headers()`, and `.extensions()` are all available.

## An authentication middleware

```rust
use serde_json::json;
use ulo::async_trait;
use ulo::http_helpers::{Body, HttpResponse};
use ulo::middleware::{Middleware, MiddlewareResult, NextHandle};

struct AuthMiddleware {
    valid_token: String,
}

#[async_trait]
impl Middleware for AuthMiddleware {
    async fn handle(&self, next: NextHandle) -> MiddlewareResult {
        let token = next
            .request()
            .headers()
            .get("authorization")
            .and_then(|v| v.to_str().ok())
            .and_then(|v| v.strip_prefix("Bearer "));

        if token == Some(self.valid_token.as_str()) {
            return next.run().await;
        }

        // Short-circuit: return a response without calling next.run()
        let mut response = HttpResponse::new();
        response.status = 401;
        response.body = Some(Body::json(json!({
            "statusCode": 401,
            "error": "Unauthorized",
            "message": "Missing or invalid Bearer token"
        })));
        Ok(response)
    }
}
```

## A logging middleware

Code after `next.run()` sees the response — the standard onion model:

```rust
pub struct LoggerMiddleware;

#[async_trait]
impl Middleware for LoggerMiddleware {
    async fn handle(&self, next: NextHandle) -> MiddlewareResult {
        let method = next.request().method().clone();
        let uri = next.request().uri().clone();

        let response = next.run().await?;
        println!("{method} {uri} -> {}", response.status);

        Ok(response)
    }
}
```

## Registering middleware

### Global middleware

Registered on the factory; runs before routing on every request:

```rust
use std::sync::Arc;
use ulo::UloFactory;

let mut factory = UloFactory::new();
factory.use_global_middleware(Arc::new(LoggerMiddleware));

let mut app = factory.create_with(AppModule).await?;
app.use_http_adapter(AxumAdapter::new(), ("127.0.0.1", 3000))?;
app.start().await?;
```

### Module-scoped middleware

Modules declare route-matched middleware in a `configure_middleware` method — use the `#[module]` attribute on an `impl` block:

```rust
use ulo::traits_helpers::MiddlewareConsumer;

#[module(controllers: [ApiController], providers: [])]
impl AppModule {
    fn configure_middleware(&self, consumer: &mut MiddlewareConsumer) {
        consumer
            .apply(LoggerMiddleware)
            .for_routes(vec!["/api/*"]);

        consumer
            .apply(AuthMiddleware { valid_token: "secret".into() })
            .exclude(vec!["/api/public/*", "/api/health"])
            .for_routes(vec!["/api/*"]);
    }
}
```

Route patterns support globs and HTTP-method filtering:

| Pattern | Matches |
|---------|---------|
| `"/users"` | Exact path, all methods |
| `"/api/*"` | Everything under `/api/`, all methods |
| `("/users", "POST")` | Only POST to `/users` |
| `("/api/*", ["GET", "POST"])` | Only GET and POST under `/api/` |

Patterns are trailing-slash-normalized to match registered routes, which never carry one — `for_route("/app/")` matches `/app`.

`apply` starts a configuration; `for_routes(vec![...])` finalizes it. `apply_also` groups several middleware onto the same routes; `for_route` / `exclude_route` add single patterns and chain, ending with `.done()` or a `for_routes` call.

### DI middleware

Middleware with injected dependencies is declared as an `#[injectable]` provider, listed in `providers`, and applied by type token — the instance is resolved from the container:

```rust
#[injectable]
pub struct AuthCheckMiddleware {
    #[inject]
    auth_service: AuthService,
}

impl AuthCheckMiddleware {
    #[new]
    pub fn new(auth_service: AuthService) -> Self {
        Self { auth_service }
    }
}

#[async_trait]
impl Middleware for AuthCheckMiddleware {
    async fn handle(&self, next: NextHandle) -> MiddlewareResult {
        if !self.auth_service.verify(next.request()).await {
            let mut response = HttpResponse::new();
            response.status = 401;
            return Ok(response);
        }
        next.run().await
    }
}
```

```rust
#[module(controllers: [ProtectedController], providers: [AuthCheckMiddleware, AuthService])]
impl ProtectedModule {
    fn configure_middleware(&self, consumer: &mut MiddlewareConsumer) {
        consumer
            .apply_token::<AuthCheckMiddleware>()
            .for_routes(vec!["/protected/*"]);
    }
}
```

`apply_token_also::<M>()` stacks additional DI middleware onto the same routes.

### Functional middleware

For one-off logic, a closure can stand in for a trait impl:

```rust
use std::sync::Arc;
use ulo::middleware::{FunctionalMiddleware, MiddlewareFn};

let log_fn: MiddlewareFn = Arc::new(|next| {
    Box::pin(async move {
        println!("-> {}", next.request().uri());
        next.run().await
    })
});
factory.use_global_middleware(Arc::new(FunctionalMiddleware::new(log_fn)));
```

## Execution order

Middleware executes in registration order on the way in and unwinds in reverse on the way out:

```
Request:  Global chain → routing → route-scoped chain → guards → interceptors → handler
Response: handler → interceptors → route-scoped chain (reverse) → Global chain (reverse)
```

<FromNest>
`configure_middleware` with a `MiddlewareConsumer` is `NestModule.configure`, and
`apply` / `for_routes` / `exclude` translate one for one. The global chain is
where they diverge: middleware registered on the factory runs *before* route
resolution on every adapter, so it sees 404s, 405s, and WebSocket upgrades, and a
URI it rewrites changes which route matches. Module-scoped middleware stays
post-routing, on the matched route only.
</FromNest>

## Reading the request body

The body arrives as `RequestBody::Streaming` — a one-time consumable stream. Middleware that only reads headers should pass the request through untouched. Middleware that must inspect the body has to buffer it and put it back, otherwise the handler receives an empty body:

```rust
use ulo::http_helpers::{HttpRequest, RequestBody};

#[async_trait]
impl Middleware for BodyInspector {
    async fn handle(&self, mut next: NextHandle) -> MiddlewareResult {
        let placeholder: HttpRequest = HttpRequest::builder()
            .method("GET")
            .uri("/")
            .body(RequestBody::empty())
            .unwrap()
            .into();
        let (parts, body) = std::mem::replace(next.request_mut(), placeholder).into_parts();

        let bytes = body.collect().await?;
        // inspect bytes...

        let new_req = HttpRequest::from_parts(parts, RequestBody::Buffered(bytes));
        next.run_with(new_req).await
    }
}
```

## Erroring from middleware

Returning `Err` from route-scoped middleware raises a `MiddlewareFailure` event and offers it to the error handler chain, so `#[catch(MiddlewareFailure)]` can reshape it. Unclaimed, it renders the canonical 500 envelope. If the boxed error is an `HttpError`, it is rendered directly with its own status instead.

A panic in route-scoped middleware takes the same route: it is caught, boxed as `PanicRecovered { during: PipelineSegment::Middleware }`, and offered to the chain, so `#[catch(PanicRecovered)]` claims it.

The global chain sits outside the dispatcher, and outside is also outside the chain: it has no error handlers to offer anything to. An unhandled `Err` there — a panic among them — is logged at `error!` and answered with the canonical envelope:

```json
{ "statusCode": 500, "message": "Internal Server Error", "error": "Internal Server Error" }
```

See [Error Handling](/docs/request-lifecycle/error-handling).

## Tower layers

With the `tower-compat` feature enabled on `ulo`, `tower::Layer` middleware plugs into the consumer directly:

```toml title="Cargo.toml"
[dependencies]
ulo = { version = "0.2", features = ["tower-compat"] }
```

```rust
use tower::ServiceBuilder;
use tower_http::cors::CorsLayer;
use tower_http::trace::TraceLayer;

fn configure_middleware(&self, consumer: &mut MiddlewareConsumer) {
    // single layer
    consumer
        .apply_tower(CorsLayer::permissive())
        .for_routes(vec!["/*"]);

    // composed stack
    let stack = ServiceBuilder::new()
        .layer(TraceLayer::new_for_http())
        .layer(CorsLayer::permissive())
        .into_inner();
    consumer
        .apply_tower(stack)
        .for_routes(vec!["/*"]);
}
```

`apply_tower` is sugar for `.apply(TowerLayer::new(layer))`; `apply_also_tower` is the chained counterpart. `TowerLayer` is re-exported at the crate root when the feature is on, so a wrapped layer can also be registered globally via `use_global_middleware`.

For CORS specifically, the built-in [`CorsMiddleware`](/docs/techniques/cors) on the global chain needs no tower dependencies.
