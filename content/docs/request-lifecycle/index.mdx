Every request travels through a predictable sequence of processing layers before the route handler runs, and through a symmetric sequence on the way back out.

## The sequence

<RequestPipeline />

Middleware and interceptors wrap what is inside them and see the response on the way out. Guards run on the way in only.

## Layer responsibilities

| Layer | Runs when | Can block? | Has response access? |
|-------|-----------|-----------|----------------------|
| Middleware | Global: before routing. Route-scoped: after routing | Yes (return a response or `Err`) | Yes (after `next.run()`) |
| Guards | Before interceptors and handler | Yes (return `false`) | No |
| Interceptors | Around handler | Yes (skip calling `next.run`) | Yes (both sides) |
| Error handlers | On a handler error, a guard rejection, a middleware `Err`, a caught panic, or a call nothing routes | — | Produce the response |

## Contexts and transports

Enhancers are generic over the per-request context. `Guard<HttpContext>` runs on HTTP routes; `Guard<RpcContext>`, `Guard<WsContext>`, and `Guard<GrpcContext>` run on RPC, WebSocket, and gRPC. The same struct can implement a trait for several contexts and serve all of those transports. Interceptors and error handlers follow the same pattern; all three roles run on all four transports.

## Scope levels

Guards, interceptors, and error handlers apply at three scopes, in execution order:

1. **Global** — registered per transport on `UloFactory`. Guards and interceptors take `use_global_{http,rpc,ws,grpc}_{guards,interceptors}`; error handlers take `use_global_{http,rpc,ws,grpc}_error_handler`. Middleware has a single global registration, `use_global_middleware`, because it is HTTP-only.
2. **Controller** — `#[use_guards]` etc. on the `#[routes]` impl block (or `#[patterns]` / `#[subscriptions]` / `#[grpc_methods]`), applies to every handler in it
3. **Method** — the same attributes on a specific handler

All levels run, in that order. Method-level runs *in addition to* controller-level and global, not instead. Error handlers run in the opposite direction — most specific first (method → controller → global), with the first claim winning.
