---
title: Interceptors
description: Interceptors wrap route handlers — they run before and after, and can transform or short-circuit.
---

An interceptor wraps a route handler and returns the answer. `next.run(context).await` yields whatever the handler (and any inner interceptors) produced; the interceptor's own return value is what goes out. Transform the returned value, replace it, or return one without calling `next.run` at all — the short-circuit for caching, circuit breakers, and canned responses.

Like guards, interceptors are generic over the per-request context and the transport's answer type `R`: `Interceptor<HttpContext, HttpResponse>` runs on HTTP routes, `Interceptor<RpcContext, RpcHandlerResult>` on RPC patterns (`Result<RpcHandlerOutput, RpcError>`), `Interceptor<WsContext, WsHandlerResult>` on WebSocket messages (`Result<WsHandlerOutput, WsError>`), `Interceptor<GrpcContext, GrpcHandlerResult>` on gRPC methods (`Result<(), GrpcStatus>`).

On RPC, an interceptor that builds its own answer rather than forwarding one names the shape: `Ok(RpcHandlerOutput::Single(data))` for one reply, `Ok(RpcHandlerOutput::Empty)` for none, `Ok(RpcHandlerOutput::Stream(s))` for a sequence.

## The Interceptor trait

```rust
use ulo::async_trait;
use ulo::context::HandlerContext;

#[async_trait]
pub trait InterceptorNext<C: ?Sized + HandlerContext, R>: Send {
    async fn run(self: Box<Self>, context: &C) -> R;
}

#[async_trait]
pub trait Interceptor<C: ?Sized + HandlerContext, R>: Send + Sync {
    async fn intercept(&self, context: &C, next: Box<dyn InterceptorNext<C, R>>) -> R;
}
```

Both live at `ulo::traits_helpers::{Interceptor, InterceptorNext}`. `run` consumes `Box<Self>`, so the downstream chain can be invoked at most once.

<FromNest>
`intercept` receives the context and a `next`, as `NestInterceptor` does — but
there is no observable and no `pipe(map(...))`. `next.run(ctx).await` returns the
response value; transform it and return it. `next` is boxed and `run` consumes
it, so it can be called at most once, and returning without calling it
short-circuits the handler.
</FromNest>

## Timing interceptor

```rust
use std::time::Instant;
use ulo::async_trait;
use ulo::context::HttpContext;
use ulo::traits_helpers::{Interceptor, InterceptorNext};
use ulo::HttpResponse;

pub struct TimingInterceptor;

#[async_trait]
impl Interceptor<HttpContext, HttpResponse> for TimingInterceptor {
    async fn intercept(
        &self,
        ctx: &HttpContext,
        next: Box<dyn InterceptorNext<HttpContext, HttpResponse>>,
    ) -> HttpResponse {
        let start = Instant::now();
        let response = next.run(ctx).await;
        println!("request took {:?}", start.elapsed());
        response
    }
}
```

## Reading the request, inspecting the response

On `HttpContext`, the request is available before `next.run` via `ctx.request()` (`&RequestPart` — method, URI, headers). The response the handler produced is what `next.run` returns:

```rust
pub struct AuditInterceptor;

#[async_trait]
impl Interceptor<HttpContext, HttpResponse> for AuditInterceptor {
    async fn intercept(
        &self,
        ctx: &HttpContext,
        next: Box<dyn InterceptorNext<HttpContext, HttpResponse>>,
    ) -> HttpResponse {
        let method = ctx.request().method.clone();
        let uri = ctx.request().uri.clone();

        let response = next.run(ctx).await;
        println!("{method} {uri} -> {}", response.status);
        response
    }
}
```

`HttpResponse` exposes `status` (a public `u16` field), `headers` (`Vec<(String, String)>`), and `body`.

## Transforming the response

The returned response is owned — mutate it or replace it before returning:

```rust
use ulo::HttpResponse;

pub struct CacheHeaderInterceptor;

#[async_trait]
impl Interceptor<HttpContext, HttpResponse> for CacheHeaderInterceptor {
    async fn intercept(
        &self,
        ctx: &HttpContext,
        next: Box<dyn InterceptorNext<HttpContext, HttpResponse>>,
    ) -> HttpResponse {
        let mut response = next.run(ctx).await;
        if response.status == 200 {
            response
                .headers
                .push(("Cache-Control".into(), "max-age=60".into()));
        }
        response
    }
}
```

## Short-circuiting

Returning without calling `next.run` skips everything downstream — inner interceptors and the handler — and the interceptor's own value is the answer:

```rust
use std::sync::atomic::{AtomicBool, Ordering};
use serde_json::json;
use ulo::HttpResponse;

pub struct MaintenanceInterceptor {
    pub enabled: AtomicBool,
}

#[async_trait]
impl Interceptor<HttpContext, HttpResponse> for MaintenanceInterceptor {
    async fn intercept(
        &self,
        ctx: &HttpContext,
        next: Box<dyn InterceptorNext<HttpContext, HttpResponse>>,
    ) -> HttpResponse {
        if self.enabled.load(Ordering::Relaxed) {
            // handler is skipped
            return HttpResponse::builder()
                .status(503)
                .json(json!({ "message": "Down for maintenance" }))
                .build();
        }
        next.run(ctx).await
    }
}
```

## Passing data to the handler

The context's typed extensions bag carries values between enhancers and handlers without coupling their types:

```rust
#[derive(Clone)]
pub struct RequestId(pub String);

#[async_trait]
impl Interceptor<HttpContext, HttpResponse> for RequestIdInterceptor {
    async fn intercept(
        &self,
        ctx: &HttpContext,
        next: Box<dyn InterceptorNext<HttpContext, HttpResponse>>,
    ) -> HttpResponse {
        ctx.extensions().insert(RequestId(new_id()));
        next.run(ctx).await
    }
}
```

Downstream enhancers read it back with `ctx.extensions().get::<RequestId>()`.

## DI-aware interceptors

Declare the interceptor as an `#[injectable]` provider and implement the trait — no marker attribute. List it in the module's `providers` and apply it by bare type name:

```rust
use ulo::injectable;

#[injectable]
pub struct WsLoggingInterceptor;

#[async_trait]
impl Interceptor<WsContext, WsHandlerResult> for WsLoggingInterceptor {
    async fn intercept(
        &self,
        ctx: &WsContext,
        next: Box<dyn InterceptorNext<WsContext, WsHandlerResult>>,
    ) -> WsHandlerResult {
        println!("client={} event={}", ctx.client().id, ctx.event());
        let result = next.run(ctx).await;
        println!("message processed");
        result
    }
}
```

```rust
#[module(
    providers: [ChatGateway, WsLoggingInterceptor],
    imports: [BroadcastModule::new()],
)]
struct ChatModule;
```

Dependencies work the same as any provider: `#[inject]` fields plus a `#[new]` constructor.

## Applying interceptors

### Controller level

`#[use_interceptors]` goes on the `#[routes]` impl block (or `#[patterns]` / `#[subscriptions]` / `#[grpc_methods]` for the other transports):

```rust
#[controller("/users")]
pub struct UsersController {}

#[routes]
#[use_interceptors(TimingInterceptor {}, CacheHeaderInterceptor {})]
impl UsersController {
    // all routes are wrapped by both interceptors
}
```

### Method level

```rust
#[routes]
impl ItemsController {
    #[use_interceptors(TimingInterceptor {})]  // only this route is timed
    #[get("/{id}")]
    fn find_one(&self) -> Body { /* ... */ }
}
```

Bare type names resolve from DI (`#[use_interceptors(WsLoggingInterceptor)]`); expressions instantiate directly (`#[use_interceptors(TimingInterceptor {})]`).

### Global (per transport)

```rust
use std::sync::Arc;

let mut factory = UloFactory::new();
factory.use_global_http_interceptors(Arc::new(TimingInterceptor));
```

`use_global_rpc_interceptors`, `use_global_ws_interceptors`, and `use_global_grpc_interceptors` register for the other transports; each takes an `Arc<dyn Interceptor<C, R>>` for the matching context and answer type.

## Execution order

Interceptors nest as onion layers, global outermost, method innermost:

```
Global (before) → Controller (before) → Method (before) → Handler
Handler → Method (after) → Controller (after) → Global (after)
```

Extractors resolve inside the handler, after the innermost interceptor has called `next.run`.

A panic inside an interceptor is caught by the framework and routed through the error pipeline instead of tearing down the request. The event is `PanicRecovered { during: PipelineSegment::Middleware }` — interceptors and middleware chain steps share one segment, so an interceptor panic reads back as `middleware` in a `#[catch(PanicRecovered)]` handler and in the logs. See [Error Handling](/docs/request-lifecycle/error-handling).
