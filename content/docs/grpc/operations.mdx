## Graceful shutdown and drain

Shutdown is signalled through the application's `ShutdownHandle` — the framework installs no signal handlers, so wire them yourself:

```rust
let mut app = UloFactory::create(AppModule).await.unwrap();
app.use_grpc_adapter(ulo_grpc::GrpcAdapter::new(addr)).unwrap();

app.bind().await.unwrap();
let shutdown = app.shutdown_handle();
tokio::task::spawn_local(async move {
    tokio::signal::ctrl_c().await.ok();
    shutdown.shutdown();
});
app.run().await;
```

On shutdown the adapter signals tonic's `serve_with_incoming_shutdown` and starts a drain timer. Tonic stops accepting connections and waits for in-flight calls — including open streams — to finish. The default budget is 10 seconds:

```rust
use std::time::Duration;

let adapter = ulo_grpc::GrpcAdapter::new(addr)
    .with_drain_timeout(Duration::from_secs(30));

// Wait without bound:
let adapter = adapter.with_drain_timeout(None);
```

When the timer elapses with calls still running, the deadline **ends** each reply still in flight rather than dropping the server under it. Every one of them closes with `UNAVAILABLE`, so the caller is told why instead of losing the connection, and a streaming handler's [cancellation token](/docs/grpc/streaming#a-reply-the-caller-abandons) fires as its reply ends. The serve future is then awaited — for the drain timeout again or two seconds, whichever is shorter — so shutdown reports complete only once tonic has closed the connections, and `close()` returns within twice the timeout you set.

The deadline is what ends a call; it does not reach inside one. A streaming handler goes on producing until its reply is ended, which is why the cancellation token is the thing to select on in a producer that would otherwise run forever.

The timer starts when shutdown is signalled, not at startup — a long-lived server is unaffected until drain begins. A never-closing bidirectional stream is the case this exists for: without the budget, one parked client would pin shutdown indefinitely.

## Backpressure

Two concurrency caps, off by default, both surfacing as `RESOURCE_EXHAUSTED`:

```rust
let adapter = ulo_grpc::GrpcAdapter::new(addr)
    .with_max_inflight(1024)        // across the whole server
    .with_max_per_connection(64);   // per client connection
```

- `with_max_inflight(n)` bounds in-flight handlers across all connections. At the cap, additional requests are **rejected immediately** (load-shed), not queued — a misbehaving client can't pin server memory by spawning unlimited calls. Permits release as calls complete.
- `with_max_per_connection(n)` bounds one connection's parallel calls, so a single client opening many streams can't monopolise the server even below the global cap.

The two stack; reaching either limit rejects the call. Pass `None` to remove a cap.

## TLS

`with_tls` takes `tonic::transport::ServerTlsConfig` as it is. Where certificates come from, how they rotate, and whether client certificates are demanded differ per deployment, so the configuration is passed through rather than wrapped:

```rust
use std::fs;
use tonic::transport::{Identity, ServerTlsConfig};

let identity = Identity::from_pem(fs::read("server.pem")?, fs::read("server.key")?);
let adapter = ulo_grpc::GrpcAdapter::new(addr)
    .with_tls(ServerTlsConfig::new().identity(identity));
```

mTLS is `ServerTlsConfig::client_ca_root`; the rest of the surface is tonic's.

The method is behind a cargo feature naming the crypto provider — the same choice tonic asks for, left where the deployment can make it. With both enabled, tonic resolves to ring.

```toml title="Cargo.toml"
ulo-grpc = { version = "0.1", features = ["tls-ring"] }   # or "tls-aws-lc"
```

The acceptor is built during `app.bind()`, so a certificate the process cannot read is a `StartupError::Adapter` from `bind()` and the socket is never opened — the first connection is not where you find out.

## Tracing

Every dispatched call runs inside a span:

```
rpc.request{transport="grpc", pattern="ulo_examples.orders.Orders/Create", id=..., peer=...}
```

`pattern` is the full proto method path; `id` is the caller's `x-request-id` metadata, falling back to `grpc-trace-id` (gRPC has no built-in correlation id); `peer` is the remote address. Events emitted from handlers and enhancers inherit these fields, so log lines correlate back to the originating call without threading context by hand.

The span surfaces out of the box: `UloFactory::create*` installs a default `tracing` subscriber (stderr, `RUST_LOG` filter, `info` fallback). To customize output, install your own subscriber before `create` — it wins over the default. See [Logging](/docs/techniques/logging).

The same `rpc.request` span shape (with `transport = "tcp"` / `"udp"`) is emitted by the RPC adapters; the repository's `rpc_tracing` example runs all three side by side.

## Mixing DI and plain tonic services

`GrpcAdapter::add_service` accepts any tonic-generated service handle, so manually built services can sit alongside the ones `#[controller]` + `#[grpc_methods]` registers:

```rust
let adapter = ulo_grpc::GrpcAdapter::new(addr)
    .add_service(SomeOtherServer::new(other_handler));
app.use_grpc_adapter(adapter).unwrap();
```

Services added this way are a passthrough to tonic — no DI, no guards, no interceptors, no error handlers, no panic recovery. A handler there reaches the execution's context, when there is one, through `GrpcContext::of(request.extensions())`; a service registered this way has none, so it answers `None`. Stock services are the usual reason to reach for it.

## Reflection and health

Both are ordinary tonic services, so both arrive through `add_service`. Neither is a dependency of `ulo-grpc` and neither has a builder knob on the adapter.

Reflection lets `grpcurl` and its kin explore the server without a local `.proto`. What it serves is the compiled schema, so `build.rs` has to write the descriptor set out:

```rust title="build.rs"
let descriptor = std::path::PathBuf::from(std::env::var("OUT_DIR")?)
    .join("orders_descriptor.bin");
tonic_prost_build::configure()
    .file_descriptor_set_path(&descriptor)
    .compile_protos(&["proto/orders.proto"], &["proto"])?;
ulo_build::shapes("ulo_examples.orders")?;
```

```rust
const DESCRIPTOR: &[u8] =
    include_bytes!(concat!(env!("OUT_DIR"), "/orders_descriptor.bin"));

let reflection = tonic_reflection::server::Builder::configure()
    .register_encoded_file_descriptor_set(DESCRIPTOR)
    .build_v1()?;
let adapter = ulo_grpc::GrpcAdapter::new(addr).add_service(reflection);
```

`grpcurl -plaintext 127.0.0.1:50051 list` then answers with the services the framework registered from `#[grpc_methods]` — reflection and DI discovery reach the same route set.

Register the versions the callers need: newer tooling speaks `grpc.reflection.v1`, older speaks `grpc.reflection.v1alpha`, and `build_v1alpha()` is the other constructor. Which schemas a server exposes is a policy decision, which is why it is written out rather than switched on.

`tonic-health` works the same way. `tonic_health::server::health_reporter()` hands back a service and a reporter; the service goes to `add_service`, and the reporter is what your own code drives as dependencies come and go. For health over HTTP instead, see [health checks](/docs/techniques/health).

## Bound address

The socket binds synchronously inside `app.bind()`, so a port conflict surfaces there as `Err` rather than a panic in the serve loop. The bound address comes back in `BoundAdapters`:

```rust
let bound = app.bind().await.unwrap();
let grpc_addr = bound.grpc.expect("gRPC adapter registered");
println!("gRPC listening on {grpc_addr}");
```

`bound.grpc` is `Option<SocketAddr>` — `None` when no gRPC adapter is registered. Binding to port 0 and reading the real port back from `bound.grpc` is the pattern the integration suite uses for test isolation.

## Adopting a pre-bound listener

`GrpcAdapter::from_listener(std::net::TcpListener)` serves on a socket the caller already bound and put into listening state instead of binding one — the route to systemd socket activation and zero-downtime restarts, where a supervisor holds the socket across process restarts. Pair with the `listenfd` crate to claim an inherited descriptor; see [Bind targets](/docs/techniques/bind-targets).
