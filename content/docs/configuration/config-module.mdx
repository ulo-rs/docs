title: Config Module

The `toni-config` crate provides structured, type-safe configuration backed by environment variables. Configuration loads eagerly at startup and is injectable anywhere in the DI graph via `ConfigService<T>`.

## Installation

```toml title="Cargo.toml"
[dependencies]
toni = "0.2"
toni-config = "0.1"
```

## Defining a configuration struct

Derive `Config` (plus `Clone`) on a struct with named fields. `#[env("VAR")]` names the environment variable; `#[default(expr)]` supplies a fallback:

```rust
use toni_config::Config;

#[derive(Config, Clone)]
pub struct AppConfig {
    #[env("APP_NAME")]
    #[default("toni-app".to_string())]
    pub name: String,

    #[env("APP_PORT")]
    #[default(3000u16)]
    pub port: u16,

    #[env("DATABASE_URL")]
    pub database_url: String,

    #[env("LOG_LEVEL")]
    #[default("info".to_string())]
    pub log_level: String,
}
```

`#[env]` and `#[default]` are separate attributes — there is no combined `#[env("VAR", default = ...)]` form. The default is a typed Rust expression, converted into the field type with `.into()`, so numeric fields need a typed literal (`3000u16`, not `"3000"`).

Field behavior:

- **With `#[default]`** — the default is used when the variable is unset. A set-but-unparseable value is an error, not a silent fallback.
- **Without `#[default]`** — the variable is required; loading fails with `ConfigError::MissingEnvVar` if it's missing.
- **`Option<T>`** — optional; `None` when the variable is unset. An unparseable value also becomes `None` rather than an error.

Without `#[env]`, the field name is uppercased (`log_level` reads `LOG_LEVEL`).

## Loading

`ConfigModule<T>` loads (and validates) the configuration when constructed:

```rust
use toni_config::{ConfigModule, Environment};

// From the process environment
let module = ConfigModule::<AppConfig>::from_env()?;

// From a .env file (loaded via dotenv, then read from the environment)
let module = ConfigModule::<AppConfig>::from_file(".env")?;

// From an environment-specific file: .env.development, .env.production, .env.test
let module = ConfigModule::<AppConfig>::from_env_file(Environment::current())?;

// Fail-fast variant: panics on failure
let module = ConfigModule::<AppConfig>::new();
```

<Callout type="warn" title="new() panics; the fallible constructors do not">
`from_env`, `from_file`, and `from_env_file` return `Result<ConfigModule<T>, ConfigError>`. `new()` panics on a load or validation failure — the message names the config type — so a bad configuration never reaches request handling; an embedding process or a test can catch the unwind.
</Callout>

## Registering and injecting

Import the module in `imports:`. It registers a `ConfigService<T>` provider, injectable by type:

```rust
use serde_json::json;
use toni::{controller, get, injectable, module, routes, Body};
use toni_config::{Config, ConfigModule, ConfigService};

#[injectable]
pub struct AppService {
    #[inject]
    config: ConfigService<AppConfig>,
}

impl AppService {
    pub fn get_config(&self) -> AppConfig {
        self.config.get()
    }
}

#[controller("/config")]
pub struct ConfigController {
    #[inject]
    service: AppService,
}

#[routes]
impl ConfigController {
    #[get("/")]
    fn get_config(&self) -> Body {
        let cfg = self.service.get_config();
        Body::json(json!({
            "name": cfg.name,
            "port": cfg.port,
        }))
    }
}

#[module(
    imports: [ConfigModule::<AppConfig>::from_env().unwrap()],
    controllers: [ConfigController],
    providers: [AppService],
)]
impl AppModule {}
```

`ConfigService<T>` exposes two accessors:

- `get_ref() -> &T` — borrows the loaded config; prefer this when a clone isn't needed.
- `get() -> T` — returns a clone; the target type must be inferable (annotate the binding or rely on the function's return type).

## Nested configuration

Group related settings into nested structs with `#[nested]`. The nested struct also derives `Config`, and its fields load from their own environment variables:

```rust
#[derive(Config, Clone)]
pub struct DatabaseConfig {
    #[env("DB_HOST")]
    #[default("localhost".to_string())]
    pub host: String,

    #[env("DB_PORT")]
    #[default(5432u16)]
    pub port: u16,
}

#[derive(Config, Clone)]
pub struct AppConfig {
    #[env("APP_PORT")]
    #[default(3000u16)]
    pub port: u16,

    #[nested]
    pub database: DatabaseConfig,
}
```

## Validation

Add the `validator` crate, derive `Validate` alongside `Config`, and mark fields with `#[validate(...)]`. Validation runs inside the `ConfigModule` constructors, after parsing and before the application starts:

```toml title="Cargo.toml"
[dependencies]
toni-config = "0.1"
validator = { version = "0.20", features = ["derive"] }
```

```rust
use toni_config::Config;
use validator::Validate;

#[derive(Config, Validate, Clone)]
pub struct AppConfig {
    #[env("APP_PORT")]
    #[default(8080u16)]
    #[validate(range(min = 1024, max = 65535))]
    pub port: u16,
}
```

The presence of `#[validate]` attributes is the opt-in — there is no Cargo feature. A config without them never references the `validator` crate. See [Configuration Validation](/docs/configuration/validation) for details.

## Error handling

Loading failures surface as `ConfigError`:

| Variant | Cause |
| --- | --- |
| `MissingEnvVar(String)` | A required variable (no default, not `Option`) is unset |
| `ParseError { key, message }` | The variable's value doesn't parse into the field type |
| `ValidationError(String)` | A `#[validate]` constraint failed |
| `DotenvError(...)` | `from_file`/`from_env_file` couldn't load the file |
