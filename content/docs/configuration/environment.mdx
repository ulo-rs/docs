---
title: Environment Variables
description: Reading and managing environment variables in Ulo applications.
---

Ulo applications read configuration from environment variables. The `ulo-config` crate automates this with typed structs (see [Config Module](/docs/configuration/config-module)), but you can also access environment variables directly.

## Direct access

```rust
use std::env;

let database_url = env::var("DATABASE_URL")
    .expect("DATABASE_URL must be set");

let port: u16 = env::var("PORT")
    .unwrap_or_else(|_| "3000".to_string())
    .parse()
    .expect("PORT must be a valid port number");
```

## Loading .env files

`ulo-config` loads `.env` files itself — no extra dependency or feature flag:

```rust
use ulo_config::ConfigModule;

// Loads .env into the process environment, then reads the config from it
let module = ConfigModule::<AppConfig>::from_file(".env")?;
```

For direct `std::env` access outside `ulo-config`, the `dotenv` crate works as usual:

```toml title="Cargo.toml"
[dependencies]
dotenv = "0.15"
```

```rust
dotenv::dotenv().ok();  // loads .env if it exists, silently ignores if missing
```

## .env file format

```bash
# .env
PORT=3000
HOST=127.0.0.1
DATABASE_URL=postgresql://localhost/myapp
JWT_SECRET=super-secret-key-at-least-32-chars
LOG_LEVEL=debug
```

## Environment-specific configuration

Keep one `.env.<environment>` file per environment:

```bash
# .env.development
LOG_LEVEL=debug
DATABASE_URL=postgresql://localhost/myapp_dev

# .env.production
LOG_LEVEL=error
DATABASE_URL=postgresql://prod-server/myapp
```

`ConfigModule::from_env_file` picks the file from an `Environment` value:

```rust
use ulo_config::{ConfigModule, Environment};

// Loads .env.development, .env.production, or .env.test
let module = ConfigModule::<AppConfig>::from_env_file(Environment::current())?;

// Or pin one explicitly
let module = ConfigModule::<AppConfig>::from_env_file(Environment::Production)?;
```

`Environment::current()` reads `NODE_ENV`, falling back to `APP_ENV`, and defaults to `Development` when neither is set. Recognized values are `development`/`dev`, `production`/`prod`, and `test`; anything else becomes `Environment::Custom(name)`, which maps to `.env.<name>`.

## Provider value from environment

Register environment-derived values directly in a module:

```rust
#[module(
    providers: [
        provider_value!(
            "DATABASE_URL",
            std::env::var("DATABASE_URL").expect("DATABASE_URL required")
        ),
        provider_value!(
            "PORT",
            std::env::var("PORT")
                .unwrap_or_else(|_| "3000".to_string())
                .parse::<u16>()
                .expect("PORT must be a number")
        ),
    ],
    exports: ["DATABASE_URL", "PORT"],
)]
pub struct EnvModule;
```

Consumers inject these by token: `#[inject("DATABASE_URL")] database_url: String`.
