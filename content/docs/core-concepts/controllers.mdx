title: Controllers
description: Controllers define HTTP routes and map them to handler functions.
---

A controller is a struct annotated with `#[controller("/prefix")]` that groups related HTTP route handlers under a base path. The handlers live in a sibling `impl` block marked `#[routes]`, where each method carries the HTTP verb it responds to.

## Defining a controller

```rust
use toni::{controller, get, routes, Body};

#[controller("/cats")]
pub struct CatsController;

#[routes]
impl CatsController {
    #[get("/")]
    fn find_all(&self) -> Body {
        Body::json(serde_json::json!(["Garfield", "Tom"]))
    }
}
```

The declaration has two halves:

- `#[controller("/prefix")]` goes on the **struct**. It handles dependency injection (`#[inject]` fields), the route prefix, and scope. It is complete on its own — a controller with no `#[routes]` impl is valid and registers zero routes.
- `#[routes]` goes on the **impl**. It scans the `#[get]`/`#[post]`/… methods and turns them into routes, joined with the struct's prefix.

All method paths are relative to the prefix: `#[get("/")]` matches `GET /cats`, `#[get("/{id}")]` matches `GET /cats/{id}`.

Path syntax, in brief:

- `{param}` is the canonical parameter syntax on every adapter.
- Express-style `:param` is a compile error: ``route path segment `:id` uses `:param` syntax; toni's parameter syntax is `{id}` ``.
- A colon later in a segment is a legal literal character: `/users/{id}:activate` works.
- Trailing slashes are insignificant — `#[get("/x/")]` declares the same route as `#[get("/x")]`, and two routes differing only by a trailing slash are refused as duplicates at bind.

## Route handlers

```rust
#[controller("/items")]
pub struct ItemsController {
    #[inject]
    service: ItemsService,
}

#[routes]
impl ItemsController {
    #[get("/")]          // GET    /items
    fn find_all(&self) -> Body { /* ... */ }

    #[get("/{id}")]      // GET    /items/{id}
    fn find_one(&self) -> Body { /* ... */ }

    #[post("/")]         // POST   /items
    fn create(&self) -> Body { /* ... */ }

    #[put("/{id}")]      // PUT    /items/{id}
    fn update(&self) -> Body { /* ... */ }

    #[delete("/{id}")]   // DELETE /items/{id}
    fn remove(&self) -> Body { /* ... */ }
}
```

Handlers can be sync or `async`. Beyond the four verbs, `#[sse("/path")]` declares a Server-Sent Events handler that returns a stream of events — see [Server-Sent Events](/docs/techniques/sse).

<FromNest>
`@Controller('users')` becomes `#[controller("/users")]`, but the handlers do not
move with it. A NestJS controller holds its routes in the class body; a Toni
controller holds only its injected dependencies, and the handlers live in a
second `impl` block marked `#[routes]`. A `#[get]` on a plain `impl` is not
scanned, and the route never registers.

Path parameters are written `{id}`. The `:id` form is a compile error.
</FromNest>

## Request data

Use extractors to pull data out of requests as handler parameters:

```rust
use toni::HttpError;
use toni::extractors::{Path, Query, Json};
use serde::Deserialize;

#[derive(Deserialize)]
struct SearchParams {
    q: String,
    limit: Option<i32>,
}

#[derive(Deserialize)]
struct CreateItemDto {
    name: String,
    price: f64,
}

#[routes]
impl ItemsController {
    #[get("/{id}")]
    fn find_one(&self, Path(id): Path<u32>) -> Result<Body, HttpError> {
        // id is a u32, parsed from the URL
        let item = self.service.find(id)
            .ok_or(HttpError::custom(404, "item not found"))?;
        Ok(Body::json(serde_json::to_value(item).unwrap()))
    }

    #[get("/")]
    fn search(&self, Query(params): Query<SearchParams>) -> Body {
        let results = self.service.search(&params.q, params.limit.unwrap_or(10));
        Body::json(serde_json::to_value(results).unwrap())
    }

    #[post("/")]
    fn create(&self, Json(dto): Json<CreateItemDto>) -> Body {
        let item = self.service.create(dto.name, dto.price);
        Body::json(serde_json::to_value(item).unwrap())
    }
}
```

Only one body-consuming extractor may appear per handler: `Json`, `Bytes`, `Body`, `BodyStream`, `Multipart`, and `HttpRequest` each take the single-use request body. The check is on the parameter's type rather than a list of names — a custom extractor that declares it reads the body is counted too — and a second one is a compile error naming both parameters. See [Extractors](/docs/extractors/built-in) for the full list.

## Dependency injection

Fields marked `#[inject]` are resolved from the DI container:

```rust
#[controller("/orders")]
pub struct OrdersController {
    #[inject]
    orders_service: OrdersService,
    #[inject]
    payments_service: PaymentsService,
}
```

No constructor is needed — the container fills the fields directly. When construction requires logic, or a dependency is used but not stored, tag a constructor with `#[new]` inside the `#[routes]` impl:

```rust
#[controller("/orders")]
pub struct OrdersController {
    prefix: String,
}

#[routes]
impl OrdersController {
    #[new]
    fn new(config: ConfigService) -> Self {
        // config is injected, used, and not stored
        Self { prefix: config.order_prefix() }
    }
}
```

Each `#[new]` parameter is resolved from the container by type. A bare `new()` without the attribute is not picked up. Both `OrdersService` and `PaymentsService` must be available in the module's DI scope — either listed in `providers` or exported by an imported module.

## Response types

Handlers return anything that implements `IntoResponse`: `Body`, `String`, `&str`, `serde_json::Value`, `u16` (status only), `(u16, Body)`, or a full `HttpResponse`. Fallible handlers return `Result`:

```rust
// Full control via the builder
#[post("/")]
async fn create_user(&self, Json(body): Json<serde_json::Value>) -> Result<HttpResponse, UserError> {
    let user = self.service.create_user(&body)?;
    Ok(HttpResponse::created()
        .header("Location", format!("/users/{}", user.id))
        .json(serde_json::to_value(user).unwrap())
        .build())
}

// HttpError for trivial cases that don't warrant a dedicated error type
#[get("/teapot")]
fn teapot(&self) -> Result<Body, HttpError> {
    Err(HttpError::custom(418, "I'm a teapot"))
}
```

Domain error types implementing `toni::Error` are lifted into the HTTP error envelope automatically when returned through `Result`.

## Guards on controllers

Apply guards to the whole controller by placing `#[use_guards]` on the `#[routes]` impl, or to a single route by placing it on the method:

```rust
#[routes]
#[use_guards(AuthGuard)]                 // every route in this controller
impl AdminController {
    #[get("/dashboard")]
    fn dashboard(&self) -> Body { /* ... */ }

    #[get("/logs")]
    #[use_guards(SuperAdminGuard)]       // additional guard on this route only
    fn logs(&self) -> Body { /* ... */ }
}
```

A guard is a provider implementing `Guard<HttpContext>`:

```rust
use toni::{async_trait, context::HttpContext, traits_helpers::Guard};

pub struct AuthGuard;

#[async_trait]
impl Guard<HttpContext> for AuthGuard {
    async fn can_activate(&self, ctx: &HttpContext) -> bool {
        ctx.request().headers.contains_key("x-auth-token")
    }
}
```

Controller-level guards run for every route; method-level guards run in addition, after them. See [Guards](/docs/request-lifecycle/guards) for the full model. The same placement rules apply to `#[use_interceptors]` and `#[use_error_handlers]`.

## Metadata

Attach metadata to routes with `#[set_metadata(...)]`; guards and interceptors read it back:

```rust
#[derive(Clone)]
pub struct Roles(pub &'static [&'static str]);

#[routes]
#[use_guards(RolesGuard {})]
impl PostsController {
    #[get("/")]
    #[set_metadata(Roles(&["user", "admin"]))]
    fn find_all(&self) -> Body { /* ... */ }

    #[delete("/{id}")]
    #[set_metadata(Roles(&["admin"]))]
    fn remove(&self) -> Body { /* ... */ }
}
```

Inside a guard, metadata comes from the context's `metadata()`:

```rust
use toni::{async_trait, context::{HandlerContext, HttpContext}, traits_helpers::Guard};

#[async_trait]
impl Guard<HttpContext> for RolesGuard {
    async fn can_activate(&self, ctx: &HttpContext) -> bool {
        let Some(Roles(required)) = ctx.metadata().and_then(|m| m.get::<Roles>()) else {
            return true; // no roles required
        };
        let role = ctx.request().headers.get("x-user-role")
            .and_then(|v| v.to_str().ok())
            .unwrap_or("guest");
        required.iter().any(|&r| r == role)
    }
}
```

Any `Clone + Send + Sync + 'static` type works as metadata, and multiple `#[set_metadata]` attributes can stack on one route.

`#[set_metadata]` also sits on the `#[routes]` impl block, where its entries apply to every handler below. A handler declaring the same type as its impl block overrides that entry and keeps the rest — a block-level `Roles(&["user"])` with a handler-level `Roles(&["admin"])` means the handler requires `admin`, while a block-level `RateLimit` it never mentions still applies. `get::<T>()` returns the winning (most specific) declaration; `get_all::<T>() -> &[T]` returns every declaration of `T`, least-specific first, for types whose declarations accumulate rather than replace.

## Controller scope

Controllers are singletons by default. `#[controller("/p", scope = "request")]` rebuilds the controller per request. A singleton controller that injects a request-scoped provider is elevated to request scope automatically — the framework logs a warning; declaring `scope = "request"` explicitly silences it.

## Registering controllers

Controllers must be listed in a module's `controllers` array.

```rust
#[module(
    controllers: [CatsController, ItemsController],
    providers: [CatsService, ItemsService],
)]
pub struct FeatureModule;
```
