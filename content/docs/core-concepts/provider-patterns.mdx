title: Provider Patterns
description: Value providers, factory providers, alias providers, and token providers — all the ways to put things into the DI container.
---

Beyond plain injectable services, Toni supports several provider patterns for registering non-struct values, computed results, async-initialized resources, and alternate names for existing providers.

## Service providers (the default)

The most common pattern — list the struct name:

```rust
#[module(
    providers: [UsersService, AuthService],
)]
pub struct AppModule;
```

Both `UsersService` and `AuthService` must be annotated with `#[injectable]`. The container builds each one from its fields — `#[inject]` fields are resolved from the DI graph, `#[default(expr)]` fields get their expression — or through a `#[new]`-tagged constructor when one exists. `#[new]` is the right tool when construction needs logic or a dependency is consumed without being stored; field injection covers everything else. See [Services & Providers](/docs/core-concepts/services).

## Value providers

Inject a static, pre-computed value under a string token or a type token:

```rust
#[module(
    providers: [
        provider_value!("APP_NAME", "MyApp".to_string()),
        provider_value!("PORT", 3000_u16),
        provider_value!(Duration, Duration::from_secs(60)),   // type as token
    ],
)]
pub struct AppModule;
```

Inject by token in a service field using the `#[inject("TOKEN")]` attribute:

```rust
#[injectable]
pub struct AppInfo {
    #[inject("APP_NAME")]
    name: String,

    #[inject("PORT")]
    port: u16,

    // a type registered under a custom token
    #[inject("PRIMARY_CONFIG")]
    config: ConfigService,
}
```

When no token is specified, `#[inject]` resolves by the field's type. The `#[inject("TOKEN")]` form resolves by the explicit token string.

The value must be `Clone`: the container holds one and hands each injection site a clone. Wrap what is not — `Arc<Logger>` is `Clone` whatever `Logger` is.

## Factory providers

Run a closure to produce a value, with optional dependencies:

```rust
#[module(
    providers: [
        // No dependencies
        provider_factory!("REQUEST_ID", || {
            format!("req_{}", std::time::SystemTime::now()
                .duration_since(std::time::UNIX_EPOCH).unwrap().as_millis())
        }),

        // With typed dependencies
        provider_factory!("APP_INFO", |config: ConfigService| {
            format!("App running in {} mode", config.get_env())
        }),

        // Async factory — detected by the `async` keyword
        provider_factory!("ASYNC_STATUS", async |logger: LoggerService| {
            logger.log("System initialized")
        }),
    ],
)]
pub struct AppModule;
```

Dependencies listed in the closure signature are resolved from the module's DI scope before the factory runs. The value the factory produces must be `Clone`, for the reason a value provider's must: the container runs the closure once at startup and clones the result into every injection site. A non-`Clone` product fails with ``the trait bound `Logger: Clone` is not satisfied``, pointed at the whole macro call and offering a `help:` that names a generated `__ToniFactoryProvider_*` type rather than the fix — which is to produce an `Arc<Logger>`.

A scope changes that, and goes after the closure:

```rust
provider_factory!("REQUEST_STARTED_AT", || std::time::Instant::now(), scope = "request")
```

`scope = "request"` and `scope = "transient"` both run the closure when the value is asked for rather than once at startup, so the produced value carries no `Clone` requirement. A request-scoped one is refused outside an execution, with the error naming `resolve` and `ProviderContext::standalone()`.

## Alias providers

Create an alternate token pointing to an existing provider. The same instance is returned for both tokens:

```rust
#[module(
    providers: [
        ConfigService,
        provider_alias!("Config", ConfigService),       // token → type
        provider_alias!("APP_PORT", "PORT"),             // token → token
    ],
)]
pub struct AppModule;
```

Useful when consuming code uses a different token name than the provider's type.

## Token providers

Register a type under a custom string token. Unlike listing the type in `providers`, this does **not** create the default type-token entry — the custom token is the only way to reach it:

```rust
#[module(
    providers: [
        provider_token!("PRIMARY_DB", DatabaseService),
        provider_token!("REPLICA_DB", ReplicaDatabaseService),
    ],
)]
pub struct AppModule;
```

## The `provide!` macro (unified)

`provide!` covers all of the above with one entry point. The first argument is the token; the second is auto-detected — a closure or async block becomes a factory, anything else a value:

```rust
#[module(
    providers: [
        provide!("API_KEY", "secret_key".to_string()),     // value
        provide!("MAX_CONNECTIONS", || 100_i32),           // factory
        provide!("LOGGER", |config: ConfigService| {       // factory with dep
            Logger::for_env(config.get_env())
        }),
    ],
)]
pub struct AppModule;
```

Marker functions make the variant explicit, and are the only spelling for aliases and token providers:

```rust
provide!("EXPLICIT_VALUE", value("explicit".to_string())),  // value provider
provide!("EXPLICIT_FACTORY", factory(|| compute())),        // factory provider
provide!("CACHE_ALIAS", existing(CacheService)),            // alias provider
provide!("PRIMARY_DB", provider(DatabaseService)),          // token provider
```

## Multi-providers

Several `provide!` entries can contribute to the same token; the contributions are collected into a `Vec`. Add `multi(Trait)` naming the trait every contribution implements:

```rust
#[module(
    providers: [
        PluginA,
        PluginB,
        provide!("PLUGINS", PluginA, multi(Plugin)),
        provide!("PLUGINS", PluginB, multi(Plugin)),
        PluginRegistry,
    ],
)]
pub struct AppModule;
```

The consumer injects the collection as `Vec<Arc<dyn Trait>>`:

```rust
use std::sync::Arc;

#[injectable]
pub struct PluginRegistry {
    #[inject("PLUGINS")]
    plugins: Vec<Arc<dyn Plugin>>,
}
```

`multi(Plugin)` is shorthand for `multi(dyn Plugin + Send + Sync)`. Contributions can be type paths, factory closures, or `existing(...)` references. The collection exists only where something contributes to it: a token nothing contributes to is not registered at all, and injecting it fails startup like any other missing provider.

## Exporting custom-token providers

The `exports` list in `#[module]` accepts type names, so type-token providers export directly:

```rust
#[module(
    providers: [DatabaseService],
    exports: [DatabaseService],
)]
pub struct DatabaseModule;
```

String-token providers are exported from a [dynamic module](/docs/core-concepts/modules#dynamic-modules) via `export_token`:

```rust
DynamicModule::builder("ConfigModule")
    .provider(DbUrlFactory::new(std::env::var("DATABASE_URL")?))
    .export_token("DB_URL")
    .build()
```

`DbUrlFactory` is a `ProviderFactory` — the value `.provider()` takes, and what the macros on this page generate. Writing one directly is the next section.

## Writing a provider by hand

The macros cover a value, a computed value, an alias and a renamed type. Below them are two traits, and a module builds on them directly when the construction cannot be spelled as a closure — a resource that needs a shutdown hook, a token chosen at runtime, an integration crate's `for_root`.

The split is between building and answering. A **`ProviderFactory`** runs once during the scan and produces a **`Provider`**, which answers every resolution afterwards:

```rust
use std::any::Any;
use std::sync::Arc;

use toni::{FxHashMap, async_trait};
use toni::traits_helpers::{Injectable, Provider, ProviderContext, ProviderFactory};

pub struct DbUrlFactory {
    url: String,
}

impl DbUrlFactory {
    pub fn new(url: impl Into<String>) -> Self {
        Self { url: url.into() }
    }
}

#[async_trait]
impl ProviderFactory for DbUrlFactory {
    fn get_token(&self) -> String {
        "DB_URL".to_string()
    }

    // Folded into the identity of the DynamicModule carrying this factory, so two
    // modules configured with different URLs stay distinct instead of colliding.
    fn identity_hint(&self) -> Option<String> {
        Some(self.url.clone())
    }

    async fn build(&self, _deps: FxHashMap<String, Injectable>) -> Injectable {
        let provider = DbUrlProvider { url: self.url.clone() };
        Injectable::new(Arc::new(Box::new(provider)), vec![])
    }
}

struct DbUrlProvider {
    url: String,
}

#[async_trait]
impl Provider for DbUrlProvider {
    fn get_token(&self) -> String {
        "DB_URL".to_string()
    }

    async fn execute(
        &self,
        _params: Vec<Box<dyn Any + Send>>,
        _ctx: ProviderContext,
    ) -> Box<dyn Any + Send> {
        Box::new(self.url.clone())
    }
}
```

Four things to know before writing one:

- **Both `get_token`s answer the same string.** The factory's token is what the module registers and what the dependency graph orders by; the instance it builds is filed under the provider's. Where the two disagree, nothing resolves.
- **`execute` returns `Box<dyn Any + Send>`, and the injection site downcasts it.** The boxed value has to be exactly the type the field declares — `String` here, not `&str` and not `Arc<String>` — because a mismatch surfaces as a failed downcast at resolution, not as a compile error.
- **Dependencies come through `get_dependencies`.** Return the tokens this factory needs and they arrive in `build`'s `deps` map, keyed by the same strings. The default is an empty list.
- **The `Vec` beside the provider is its role registrations.** Empty for a plain value; a provider that also implements `Guard` or `Interceptor` lists those roles so the enhancer registries find it. `#[injectable]` fills it from the trait impls it can see.

`Provider` also carries the five lifecycle hooks as defaulted no-ops. Overriding `on_module_init` is how an integration turns an unreachable server into a startup failure, and `on_application_shutdown` is where a pool is closed — the hooks a `provider_value!` or `provider_factory!` registration cannot reach.
