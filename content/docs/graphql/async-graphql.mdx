---
title: async-graphql Integration
description: Use toni-async-graphql to add a GraphQL endpoint powered by the async-graphql crate.
---

`toni-async-graphql` integrates Toni's module system with the [async-graphql](https://github.com/async-graphql/async-graphql) crate. A `ContextBuilder` populates the `async-graphql` `Data` container per-request, so resolvers can access injected Toni services.

## Installation

```toml title="Cargo.toml"
[dependencies]
toni = "0.2"
toni-async-graphql = "0.1"
async-graphql = "7"
toni-axum = "0.1"
tokio = { version = "1", features = ["full"] }
```

## 1. Define the schema

```rust
use async_graphql::{Object, Schema, EmptyMutation, EmptySubscription, Context};

pub struct QueryRoot;

#[Object]
impl QueryRoot {
    async fn users(&self, ctx: &Context<'_>) -> Vec<String> {
        let service = ctx.data::<UsersService>().unwrap();
        service.find_all_names()
    }

    async fn user(&self, ctx: &Context<'_>, id: u32) -> Option<String> {
        let service = ctx.data::<UsersService>().unwrap();
        service.find_one_name(id)
    }
}

pub type AppSchema = Schema<QueryRoot, EmptyMutation, EmptySubscription>;
```

## 2. Build the context

The `ContextBuilder` trait populates `async-graphql`'s `Data` container before each request executes. It receives the incoming `RequestPart` so you can read headers (e.g. to verify an auth token) alongside the services it carries.

The builder is passed by value to `for_root` — it is not resolved through the DI container. Construct it, and any services it captures, when building the module:

```rust
use async_graphql::Data;
use async_trait::async_trait;
use toni::RequestPart;
use toni_async_graphql::ContextBuilder;

pub struct AppContextBuilder {
    users_service: UsersService,
}

impl AppContextBuilder {
    pub fn new(users_service: UsersService) -> Self {
        Self { users_service }
    }
}

#[async_trait]
impl ContextBuilder for AppContextBuilder {
    async fn build(&self, _req: &RequestPart) -> Data {
        let mut data = Data::default();
        data.insert(self.users_service.clone());
        data
    }
}
```

When you don't need context data, use the built-in `DefaultContextBuilder`:

```rust
use toni_async_graphql::{GraphQLModule, DefaultContextBuilder};

let graphql_module = GraphQLModule::for_root(schema, DefaultContextBuilder);
```

## 3. Register the GraphQL module

Module `imports` entries are expressions, so a helper function that builds the schema and the context builder keeps the declaration readable:

```rust
use toni_async_graphql::GraphQLModule;

fn graphql_module() -> GraphQLModule<QueryRoot, EmptyMutation, EmptySubscription, AppContextBuilder> {
    let schema = Schema::build(QueryRoot, EmptyMutation, EmptySubscription).finish();
    GraphQLModule::for_root(schema, AppContextBuilder::new(UsersService::new()))
        .with_path("/graphql")       // default: "/graphql"
        .with_playground(true)       // default: enabled in debug builds, disabled in release
}

#[module(
    imports: [graphql_module(), UsersModule],
)]
pub struct AppModule;
```

## 4. Wire up in main

```rust
use toni::ToniFactory;
use toni_axum::AxumAdapter;

#[tokio::main]
async fn main() {
    let mut app = ToniFactory::create(AppModule).await.unwrap();
    app.use_http_adapter(AxumAdapter::new(), ("127.0.0.1", 3000)).unwrap();
    app.start().await.unwrap();
}
```

`POST /graphql` handles queries and mutations. In debug builds, `GET /graphql` serves GraphQL Playground.

## Mounting more than one schema

A `GraphQLModule`'s identity is its full type — query, mutation and subscription roots and the context builder — plus the path, the playground flag and the subscription path. Two imports differing in any of those are two modules, which decides what happens when a graph holds more than one:

- The same schema at two paths mounts two endpoints, each with its own context builder.
- An identical import reached through two module paths is a diamond: one module, one endpoint.
- Two modules on one path is a duplicate route, and the adapter's own router is what rejects it: registration panics out of `app.bind()` rather than returning a `StartupError` — axum's message is `Overlapping method route`. Give each endpoint its own path.

Changing only the context builder does not merge two modules onto one path; it makes them distinct, so the third case is what you get.

## Reading request headers in context

Use `req` in `build` to read HTTP headers — useful for extracting auth tokens:

```rust
#[async_trait]
impl ContextBuilder for AppContextBuilder {
    async fn build(&self, req: &RequestPart) -> Data {
        let mut data = Data::default();

        if let Some(auth) = req.headers.get("authorization") {
            if let Ok(header_val) = auth.to_str() {
                if let Some(user) = self.auth_service.verify(header_val).await {
                    data.insert(user);
                }
            }
        }

        data.insert(self.users_service.clone());
        data
    }
}
```

## Injecting the service

`GraphQLModule` exports the executor behind the endpoint under the token `"GraphQLService"`. A module that imports the GraphQL module can inject it and run a document without going through HTTP — a scheduled job, or a second protocol in front of the same schema:

```rust
use toni_async_graphql::{DefaultContextBuilder, GraphQLService};

type AppGraphQL = GraphQLService<QueryRoot, EmptyMutation, EmptySubscription, DefaultContextBuilder>;

#[injectable]
pub struct ReportJob {
    #[inject("GraphQLService")]
    graphql: AppGraphQL,
}
```

The registration token is that string, so a bare `#[inject]` by type does not reach the service. Name it, and spell out all four parameters of `GraphQLService<Query, Mutation, Subscription, Ctx>` — an alias keeps that to one place.

`execute` takes the `RequestPart` it hands to your `ContextBuilder`, so a caller outside a request supplies one of its own.

## Subscriptions

Enable GraphQL subscriptions over the `graphql-transport-ws` protocol by calling `.with_subscription_path()`:

```rust
let schema = Schema::build(QueryRoot, EmptyMutation, SubscriptionRoot).finish();

let graphql_module = GraphQLModule::for_root(schema, DefaultContextBuilder)
    .with_path("/graphql")
    .with_subscription_path("/graphql/ws");
```

Clients connect via WebSocket and must negotiate the `graphql-transport-ws` sub-protocol (graphql-ws v5+):

```
ws://localhost:3000/graphql/ws
Sec-WebSocket-Protocol: graphql-transport-ws
```

A connection that does not offer that sub-protocol is refused with close code 4406 — the code `graphql-transport-ws` reserves for an unacceptable sub-protocol — and nothing else is sent. A client that has not agreed on the grammar cannot read an error written in it.

### Subscription context

Use `.with_subscription_context()` to inject per-connection data into subscription resolvers. The builder receives a `&WsClient` (carrying handshake headers) and the `connection_init` payload. Like the request-context builder, it is passed by value and constructed by hand:

```rust
use async_graphql::Data;
use async_trait::async_trait;
use serde_json::Value;
use toni::WsClient;
use toni_async_graphql::SubscriptionContextBuilder;

pub struct AppSubscriptionContextBuilder {
    auth_service: AuthService,
}

impl AppSubscriptionContextBuilder {
    pub fn new(auth_service: AuthService) -> Self {
        Self { auth_service }
    }
}

#[async_trait]
impl SubscriptionContextBuilder for AppSubscriptionContextBuilder {
    async fn build(&self, client: &WsClient, init_payload: Option<Value>) -> Data {
        let mut data = Data::default();

        if let Some(token) = init_payload
            .as_ref()
            .and_then(|p| p.get("authToken"))
            .and_then(|t| t.as_str())
        {
            if let Some(user) = self.auth_service.verify(token).await {
                data.insert(user);
            }
        }

        data
    }
}

// Wire it in:
GraphQLModule::for_root(schema, DefaultContextBuilder)
    .with_subscription_path("/graphql/ws")
    .with_subscription_context(AppSubscriptionContextBuilder::new(auth_service))
```

When you don't need subscription context data, `DefaultSubscriptionContextBuilder` is used automatically.

### Example subscription schema

```rust
use async_graphql::{Object, Schema, EmptyMutation, Subscription, Context};
use futures::Stream;
use futures::stream;

pub struct QueryRoot;

#[Object]
impl QueryRoot {
    async fn ping(&self) -> &str { "pong" }
}

pub struct SubscriptionRoot;

#[Subscription]
impl SubscriptionRoot {
    async fn countdown(&self, from: i32) -> impl Stream<Item = i32> {
        stream::iter((0..=from).rev())
    }
}

pub type AppSchema = Schema<QueryRoot, EmptyMutation, SubscriptionRoot>;
```

## API reference

```rust
use toni_async_graphql::{GraphQLModule, ContextBuilder, DefaultContextBuilder,
                         SubscriptionContextBuilder, DefaultSubscriptionContextBuilder};

// Module builder
GraphQLModule::for_root(schema, context_builder) -> GraphQLModule<Q, M, S, Ctx>
    .with_path(impl Into<String>) -> Self                    // HTTP endpoint (default: "/graphql")
    .with_playground(bool) -> Self                           // toggle playground (default: debug_assertions)
    .with_subscription_path(impl Into<String>) -> Self       // WebSocket endpoint for subscriptions
    .with_subscription_context(impl SubscriptionContextBuilder) -> Self

// ContextBuilder trait (for queries/mutations)
#[async_trait]
trait ContextBuilder: Send + Sync + 'static {
    async fn build(&self, req: &RequestPart) -> async_graphql::Data;
}

// SubscriptionContextBuilder trait
#[async_trait]
trait SubscriptionContextBuilder: Send + Sync + 'static {
    async fn build(&self, client: &WsClient, init_payload: Option<Value>) -> async_graphql::Data;
}

// No-op implementations
struct DefaultContextBuilder;
struct DefaultSubscriptionContextBuilder;

// The exported executor, registered and exported under the token "GraphQLService"
impl GraphQLService<Query, Mutation, Subscription, Ctx> {
    async fn execute(
        &self,
        query: String,
        operation_name: Option<String>,
        variables: Option<serde_json::Value>,
        http_req: &RequestPart,
    ) -> async_graphql::Response;

    fn schema(&self) -> &async_graphql::Schema<Query, Mutation, Subscription>;
}
```
