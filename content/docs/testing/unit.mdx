title: Unit Testing
description: Testing individual services, guards, and interceptors in isolation.
---

Unit tests in Ulo are ordinary Rust unit tests — no harness, no test module. A service is a plain struct: instantiate it and call its methods.

## Testing a service

```rust
#[injectable]
pub struct MathService;

impl MathService {
    #[new]
    pub fn new() -> Self { Self }

    pub fn add(&self, a: i32, b: i32) -> i32 { a + b }
    pub fn divide(&self, a: f64, b: f64) -> Option<f64> {
        if b == 0.0 { None } else { Some(a / b) }
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_add() {
        let service = MathService::new();
        assert_eq!(service.add(2, 3), 5);
        assert_eq!(service.add(-1, 1), 0);
    }

    #[test]
    fn test_divide_by_zero() {
        let service = MathService::new();
        assert_eq!(service.divide(10.0, 0.0), None);
    }

    #[test]
    fn test_divide() {
        let service = MathService::new();
        assert_eq!(service.divide(10.0, 2.0), Some(5.0));
    }
}
```

`#[new]` marks the DI constructor, and passes the method through unchanged — tests call `MathService::new()` like any constructor.

<FromNest>
There is no `Test.createTestingModule()` step. A service is a struct: construct
it, call the method, assert. Reach for `UloFactory::create_application_context`
only when a test needs the container itself — resolution through tokens, request
scope, or lifecycle hooks.
</FromNest>

## Testing services with dependencies

Construct dependencies manually for unit tests:

```rust
#[cfg(test)]
mod tests {
    use super::*;

    fn make_orders_service() -> OrdersService {
        // Construct with real (or mock) dependencies
        let users_service = UsersService::new();
        let payments_service = PaymentsService::new();
        OrdersService::new(users_service, payments_service)
    }

    #[tokio::test]
    async fn test_create_order() {
        let service = make_orders_service();
        let result = service.create_order(1, 99.99).await;
        assert!(result.is_ok());
    }
}
```

## Testing guards

Guards implement `Guard<HttpContext>` (or another context type) with an async `can_activate`. Build a request with `HttpRequest::builder()`, wrap it in an `HttpContext`, and await the guard directly:

```rust
use ulo::async_trait;
use ulo::context::HttpContext;
use ulo::traits_helpers::Guard;
use ulo::injectable;

#[injectable]
pub struct AuthGuard;

#[async_trait]
impl Guard<HttpContext> for AuthGuard {
    async fn can_activate(&self, ctx: &HttpContext) -> bool {
        ctx.request()
            .headers
            .get("authorization")
            .and_then(|v| v.to_str().ok())
            .map(|h| h.starts_with("Bearer "))
            .unwrap_or(false)
    }
}

#[cfg(test)]
mod tests {
    use super::*;
    use ulo::{HttpRequest, RequestBody};

    fn context_with_token(token: &str) -> HttpContext {
        let req = HttpRequest::builder()
            .uri("/protected")
            .header("authorization", format!("Bearer {token}"))
            .body(RequestBody::empty())
            .unwrap();
        HttpContext::from_request(req)
    }

    #[tokio::test]
    async fn allows_valid_token() {
        let guard = AuthGuard;
        let ctx = context_with_token("valid-token-123");
        assert!(guard.can_activate(&ctx).await);
    }

    #[tokio::test]
    async fn blocks_missing_token() {
        let guard = AuthGuard;
        let req = HttpRequest::builder()
            .uri("/protected")
            .body(RequestBody::empty())
            .unwrap();
        let ctx = HttpContext::from_request(req);
        assert!(!guard.can_activate(&ctx).await);
    }
}
```

`HttpRequest::builder()` is the `http` crate's request builder — chain `.method(...)`, `.uri(...)`, and `.header(...)` as needed, then finish with `.body(RequestBody::empty())` (or `RequestBody::Buffered(bytes)` for a request with a body). `HttpContext::from_request` accepts the result directly.

## Request-scoped providers

A request-scoped provider only exists inside an execution, so tests resolve it against one. `ProviderContext::standalone()` builds a transportless execution:

```rust
use ulo::{ProviderContext, UloFactory};

let app = UloFactory::create(TestModule).await.unwrap();
let execution = ProviderContext::standalone();

let service = app.resolve::<RequestScopedService>(&execution).await.unwrap();
```

Everything resolved against the same execution shares one instance cache — a request-scoped type is built once and handed to each of them — and dropping the handle ends the execution. Resolving a request-scoped provider outside an execution is refused with an error, not a panic.

## Testing async services

Use `#[tokio::test]` for async tests:

```rust
#[cfg(test)]
mod tests {
    use super::*;

    #[tokio::test]
    async fn test_database_service() {
        let service = DatabaseService::new();
        // on_module_init won't run automatically in unit tests
        // Call it manually if needed:
        // service.connect().await;

        let users = service.find_all().await;
        assert!(!users.is_empty());
    }
}
```

## Mocking dependencies

For true isolation, create mock implementations of your traits. The `mockall` crate is popular for this:

```toml title="Cargo.toml"
[dev-dependencies]
mockall = "0.13"
```

```rust
use mockall::mock;

mock! {
    UserRepository {}

    impl UserRepository {
        fn find_by_id(&self, id: u32) -> Option<User>;
        fn save(&self, user: &User) -> Result<(), String>;
    }
}

#[test]
fn test_with_mock() {
    let mut mock_repo = MockUserRepository::new();
    mock_repo.expect_find_by_id()
        .with(mockall::predicate::eq(1u32))
        .returning(|_| Some(User { id: 1, name: "Alice".into() }));

    let service = UserService::with_repository(mock_repo);
    let user = service.find(1);
    assert_eq!(user.unwrap().name, "Alice");
}
```
